# 팀 소개 페이지 PRD — 브릿지팀 (Team Bridge)

## 1. 개요
| 항목 | 내용 |
|---|---|
| 팀 이름 | 브릿지팀 (Team Bridge) — 가상의 팀 |
| 한 줄 정의 | 부서와 부서 사이의 일을 잇고, 반복 업무를 도구로 바꾸는 팀 |
| 만드는 것 | 한 페이지짜리 팀 소개 웹페이지 (`index.html`) |
| 목표 | 처음 보는 사람이 1분 안에 "이 팀이 무슨 일을 하고, 뭘 부탁하면 되고, 어디로 연락하는지" 알게 한다 |

## 2. 누가 보나
| 대상 | 궁금한 것 | 페이지가 줘야 할 답 |
|---|---|---|
| 협업 부서 | 이 일을 이 팀에 부탁해도 되나? 어떻게 요청하지? | 업무 범위 카드 + 요청 방법 |
| 신규 입사자 | 이 팀은 뭐 하는 곳이지? 누구한테 물어보지? | 한 줄 소개 + 담당 채널 |

## 3. 메뉴 (상단 고정 내비게이션)
1. **소개** — 팀 한 줄 소개, 팀이 일하는 방식
2. **하는 일** — 업무 카드 4장
3. **우리가 만든 도구** — 지금은 "준비 중" 카드로 표시
4. **문의** — 요청 채널, 이메일, 응답 시간

메뉴를 누르면 해당 섹션으로 부드럽게 스크롤한다. 휴대폰에서는 메뉴가 햄버거 버튼 안으로 들어간다.

## 4. 화면 순서
```
[헤더: 로고 + 메뉴]
   ↓
① 한 줄 소개 (히어로)
   "부서 사이의 일을 잇는 팀, 브릿지입니다."
   보조 문구 1줄 + [요청하기] 버튼(→ 문의로 이동)
   ↓
② 업무 카드 (하는 일)
   카드 4장: 아이콘 · 제목 · 설명 2줄
   - 업무 프로세스 정리
   - 반복 업무 자동화
   - 사내 도구 운영
   - 협업 가이드 · 온보딩
   ↓
③ 우리가 만든 도구
   카드 3장, 모두 "준비 중" 배지
   ↓
④ 문의
   요청 채널(슬랙) · 이메일 · 응답 시간 안내
   ↓
[푸터: 팀 이름 · 연도]
```

## 5. 분위기
| 항목 | 내용 |
|---|---|
| 메인 색 | 남색 `#1E2A5A` |
| 보조 색 | 밝은 하늘 `#E8EEFB`, 포인트 `#4C6FFF` |
| 배경 | 흰색 · 아주 연한 회색 섹션 교차 |
| 느낌 | 차분하고 믿음직한, 여백이 넉넉한, 군더더기 없는 |
| 글꼴 | Pretendard (없으면 시스템 기본 산세리프) |
| 모서리 | 카드 둥글게 (16px), 그림자는 아주 옅게 |

## 6. 요구사항
- 파일 하나(`index.html`)로 동작, 별도 빌드 없음
- 로고: `images/logo.png`
- 휴대폰(375px)부터 데스크톱까지 깨지지 않는 반응형
  - 업무 카드: 데스크톱 4열 → 태블릿 2열 → 휴대폰 1열
- "우리가 만든 도구"는 실제 도구 대신 **"준비 중"** 카드

## 7. 범위 밖
- 로그인, 게시판, 문의 폼 전송(서버) 기능
- 실제 도구 링크 (도구가 나오면 카드만 교체)

## 8. 완료 기준
- [ ] 메뉴 4개가 각 섹션으로 이동한다
- [ ] 화면 순서가 한 줄 소개 → 업무 카드 → (도구) → 문의 순이다
- [ ] 휴대폰 폭에서 가로 스크롤이 생기지 않는다
- [ ] 로고가 헤더에 보인다
