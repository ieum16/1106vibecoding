# 우사기 테크 브리핑 2.0 구현·검증 기록

## 분석한 구조
- Manifest V3, 일반 HTML/CSS/JavaScript. 프레임워크·번들러·서버·런타임 패키지 의존성 없음.
- 기존 popup.js: 할 일 CRUD와 chrome.storage.local의 todos, Open-Meteo 현재 날씨 요청.
- 기존 news.js: GeekNews Atom/RSS를 DOMParser로 읽고 텍스트로 렌더링, savedArticles 스크랩, 접근 권한 처리, 15분 갱신.
- 기존 news-rules.js: 서울 날짜, 주제 분류와 활용 가이드 템플릿.
- 기존 popup.html / popup.css / assets/usagi.png를 기반으로 화면 개편. 이미지 에셋 추가 없음.

## 변경 파일
- manifest.json: 서비스 이름, 2.0.0 버전. storage 및 기존 두 API 호스트 권한 유지.
- popup.html / popup.css: 460×600 팝업, 우사기 히어로·작은 정보 표시·세 책갈피 탭·팝업 전체 내부 세로 스크롤·오류와 빈 상태·키보드 포커스·모션 감소.
- ui.js (추가): 탭, 대시보드 숫자, 진행률, 키워드 필터, 일일 팁, 전역 완료 피드백.
- popup.js: 기존 날씨 로직 재사용. 할 일 쓰기 직렬화, 저장 성공 후 화면 반영, 관련 기사·아이디어 보관, 기존 항목 강조.
- news.js: 기존 수집·권한·자동 갱신 재사용. 카테고리 카드, 활용 아이디어, 탭과 대시보드 연결, 원본 스크랩 데이터 보존.
- news-rules.js: 기존 날짜·중복 관련 정책 유지, 분야별 중요성·환경·활용 목적, 제목에서 키워드 추출, UI의 실험 용어 정리.
- README.md / 이 문서 / screenshot*.png / tests/*.cjs: 사용 안내와 검증 기록.

## 상태 및 이벤트
- 저장 데이터의 기준은 기존 chrome.storage.local. todos와 savedArticles 키를 변경하지 않음.
- 할 일은 수정 전 최신 저장값을 읽고 같은 페이지의 쓰기를 큐로 직렬화. 저장 실패 시 화면을 성공 상태로 바꾸지 않음.
- storage.onChanged로 다른 열린 확장 화면의 변경을 반영.
- UsagiUI가 탭·집계 표시를 담당. usagi-tab, usagi-keyword 이벤트로 뉴스 화면과 연동.
- 뉴스 갱신·날짜 검사·일일 팁 타이머는 각 스크립트 초기화 시 한 번 등록하고 pagehide에서 정리.

## 데이터 호환성
기존 배열을 읽으며, 기존 객체의 알 수 없는 추가 필드도 유지합니다. 로딩만으로 데이터를 다시 쓰지 않습니다. 별도의 일괄 마이그레이션이나 저장소 삭제를 하지 않으므로 중복 마이그레이션도 없습니다.

기존 할 일 필드: id, text, completed, 선택적 articleUrl.
새 뉴스 할 일 추가 필드: articleId(기사 URL 기반 식별자), articleUrl, articleTitle, ideaId, idea, createdAt.
idea에는 표시명·활용 목적·중요성·환경·3단계·분야 ID를 담습니다.
일반 할 일에는 createdAt만 추가됩니다. 기존 완료 여부·본문·링크는 그대로 유지됩니다.

중복 판정은 정규화한 기사 URL과 ideaId 조합입니다. 이전 데이터처럼 ideaId가 없는 기사 할 일은 같은 URL이면 기존 항목으로 이동합니다.
잘못된 저장값을 발견하면 안내하고 해당 저장소를 덮어쓰지 않습니다. 유효한 기존 스크랩은 날짜와 상관없이 표시합니다.

## 개발자 정보
- 진행률: 현재 보관 중인 전체 할 일의 완료/전체. 할 일이 없으면 0%와 시작 안내.
- 키워드: 오늘 선별된 기사 제목의 명시적 기술명만 추출. 기사 단위 빈도 내림차순, 동점은 문자열 오름차순. 중복 제외 최대 3개. 데이터가 없으면 가짜 태그를 만들지 않음.
- 팁: 3개의 검증된 로컬 팁을 서울 날짜 순번으로 순환. 같은 날짜는 같은 팁이고 다음 날짜는 다음 팁. Git diff, JavaScript ??, Response.ok 공식 문서를 각 팁에 연결.
- 날씨: 기존 서울 좌표·섭씨·Asia/Seoul·10초 타임아웃 유지. 오류는 날씨 영역에 표시.

## 실행한 검증
Windows의 별도 임시 프로필에서 Microsoft Edge(Chromium)의 실제 확장 로딩을 사용했습니다. 개인 브라우저의 저장 데이터나 설정을 테스트에 사용하지 않았습니다.

tests/usagi.test.cjs:
- 기존 할 일·완료 여부·기사 링크·사용자 정의 필드·어제 스크랩이 로딩 후 그대로 보존됨
- 일반 할 일 추가/완료/삭제, 전체·완료·남은 개수와 진행률 업데이트
- 오늘 기사 최대 5개, 중복 기사와 일반 사건 제외
- 아이디어 펼치기, 3단계와 새 메타데이터 저장, 같은 아이디어 재추가 방지
- 저장/해제와 대시보드 즉시 반영, 날짜가 지난 스크랩 보존
- 키워드 필터, 데이터 없는 날짜에 키워드 비움
- 같은 날 팁 유지, 다음날 팁 변경, 날짜 경계에서 오늘 목록 비움
- 저장 실패 시 기존 데이터 보존
- RSS와 날씨 503 오류 시 할 일 화면 계속 사용 가능
- 방향키 탭 이동, 가로 넘침 없음, 처리되지 않은 JavaScript 오류 없음
- 브라우저 프로세스를 닫고 같은 테스트 프로필로 재실행해 데이터 보존 확인

tests/live-preview.cjs:
- 실제 RSS에서 기술 기사 5개와 실제 서울 기온 수신
- Manifest 호스트 권한이 기존 두 API로 제한됨
- 브리핑 → 스크랩 → 활용 아이디어 → 할 일 전환
- 정상 요청 환경에서 콘솔 error 및 pageerror 없음
- 실제 화면 3장 촬영 후 시각 확인

추가 확인: node --check로 런타임 JS 문법 검사, git diff --check.
별도 빌드 과정은 없습니다.

## 테스트 실행
테스트용 Playwright는 확장프로그램의 런타임 의존성이 아닙니다.
이 환경에는 임시 도구 폴더에 설치된 Playwright를 사용했습니다.

PowerShell:
```powershell
$env:NODE_PATH = "$env:TEMP\codex-news-check\node_modules"
node tests/usagi.test.cjs
node tests/live-preview.cjs
```
다른 환경에서는 Playwright를 테스트 도구로 설치하고, 필요하면 USAGI_BROWSER에 Chromium 기반 브라우저 실행 경로를 지정합니다. 테스트의 확장 관리 페이지는 Edge 기준입니다. live-preview는 네트워크와 오늘의 해당 기사가 있어야 통과합니다.

## 한계·미검증
- 일반 Chrome의 사용자 실제 프로필을 조작하거나 그 안의 데이터로 검증하지 않았습니다. Chromium 확장 테스트는 Edge에서 수행했습니다.
- 키워드 규칙은 의미 분석이 아니므로 누락·오분류 가능. RSS 밖의 뉴스는 검색하지 않습니다.
- 활용 아이디어는 원문 전체 검증이나 AI 생성이 아닌 분야별 일반 제안입니다.
- 완료율은 날짜별 계획이 아니라 보관 중인 전체 할 일 기준입니다. 기존 항목의 생성일을 추측해 넣지 않습니다.
- 저장 쓰기는 한 팝업 안에서 직렬화하며 다른 창 변경도 반영하지만, 여러 창이 정확히 동시에 쓰는 상황의 완전한 트랜잭션은 보장하지 않습니다.
- 스크린리더 실제 기기, 모든 OS/브라우저 조합, 장기간 네트워크 불안정은 미검증입니다.
- 개발자 팁은 현재 3개를 날짜별 순환합니다.
- 인증·배포·원격 push·실제 사용자 데이터 삭제는 수행하지 않았습니다.

## 다시 로드
기존 설치 폴더를 유지한 채 chrome://extensions에서 해당 확장프로그램을 새로고침하고 팝업을 다시 엽니다. 확장프로그램을 삭제 후 재설치하지 마세요. 삭제하면 브라우저가 해당 확장 저장 데이터를 제거할 수 있습니다.

## 귀여운 테마 보완
큰 기존 우사기 이미지와 말풍선·낙서, 종이색 배경을 복원했습니다. 숫자 카드는 작은 표시로, 검은 선택 탭은 노란 책갈피 스타일로 바꿨습니다. 스크롤 시 캐릭터 영역은 올라가고 탭은 상단에 남습니다. 데이터 구조 변경 없이 기존 자동화 테스트와 실제 API·화면 검증을 다시 통과했습니다.
