# 메일 정리함 · Outlook 업무 도우미

Outlook 받은편지함을 키워드 규칙에 따라 정리하는 Chrome 확장 프로그램입니다.
별도 서버, 빌드, 패키지 설치 없이 사용할 수 있습니다.

## 1. Chrome에 설치

1. Chrome 주소창에 `chrome://extensions`를 입력합니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 이 폴더 `압축 해제한 확장 프로그램 폴더`을 선택합니다. `manifest.json`이 바로 들어 있는 폴더여야 합니다.
5. Chrome 도구 모음의 확장 프로그램 메뉴에서 **메일 정리함 · Outlook 업무 도우미**를 누릅니다. 관리 화면이 새 탭으로 열립니다.

ZIP 파일을 받은 경우 먼저 압축을 풀고, 압축 해제한 폴더 중 `manifest.json`이 들어 있는 폴더를 선택하세요.
`dashboard.html`을 탐색기에서 직접 여는 방식으로는 작동하지 않습니다.

## 2. 실제 메일 없이 먼저 체험

1. **샘플로 체험**을 누릅니다.
2. **미리보기 조회**를 누르면 샘플 메일 6개 중 5개의 이동 경로가 표시됩니다.
3. **분류 실행**을 누르면 샘플을 폴더별로 분류합니다. 스팸 샘플은 정크 메일로 이동합니다.
4. **현재 작업 되돌리기**를 누르면 원래 위치로 복구합니다.

샘플 모드에서는 Microsoft에 요청하거나 실제 메일을 변경하지 않습니다.
샘플 모드에서 실제 계정으로 연결하면 샘플 규칙과 기록을 지우므로 실제 폴더를 기준으로 규칙을 새로 등록하세요.

## 3. Outlook 실제 계정 연결

실제 메일에 접근하려면 본인 또는 회사에서 등록한 Microsoft 애플리케이션 ID가 필요합니다.
이 프로젝트에는 다른 사람의 앱 ID나 비밀키가 들어 있지 않습니다.

1. 확장 프로그램 화면의 **연결 설정**에서 **리디렉션 URI 복사**를 누릅니다.
2. [Microsoft Entra 관리 센터](https://entra.microsoft.com/)에서 **앱 등록 → 새 등록**을 엽니다.
3. 앱 이름을 입력하고 계정 유형을 선택합니다.
   - 회사 계정과 Outlook.com을 모두 쓰려면 조직 디렉터리 및 개인 Microsoft 계정을 지원하는 유형을 선택합니다.
   - 회사 전용 단일 테넌트 앱이면 확장 프로그램의 테넌트에 해당 디렉터리 ID를 입력합니다.
4. 등록 후 **인증 → 플랫폼 추가 → 단일 페이지 애플리케이션(SPA)**을 선택합니다.
5. 복사한 `https://<확장프로그램-ID>.chromiumapp.org/` 주소를 리디렉션 URI에 그대로 등록합니다. 끝의 `/`까지 일치해야 합니다.
6. **API 사용 권한 → 권한 추가 → Microsoft Graph → 위임된 권한**에서 다음을 추가합니다.
   - `User.Read`: 연결한 계정 확인
   - `Mail.ReadWrite`: 메일 조회와 폴더 이동
7. 확장 프로그램에 **애플리케이션(클라이언트) ID**를 입력하고 **연결 설정 저장**을 누릅니다. 일반적인 테넌트 값은 `common`입니다.
8. **Outlook 연결**을 누르고 본인 계정으로 로그인하고 권한에 동의합니다. `offline_access`는 로그인 갱신을 위해 요청합니다.

클라이언트 비밀키는 만들거나 입력하지 않습니다. Authorization Code + PKCE 방식을 사용합니다.
회사에서 앱 등록 또는 메일 권한 동의를 제한하면 관리자의 등록·승인이 필요합니다.
다른 경로 또는 다른 Chrome 프로필에서 확장 프로그램 ID가 달라지면 화면에 표시된 리디렉션 URI로 앱 등록을 갱신하세요.

## 4. 업무 메일 분류

1. Outlook에 사용할 목적지 폴더를 미리 만듭니다. 폴더를 추가했다면 확장 프로그램에서 **폴더 새로고침**을 누릅니다.
2. 규칙 이름, 검색 위치(제목/보낸 사람/본문/전체), 키워드, 일치 조건과 목적지 폴더를 선택합니다.
3. 키워드는 쉼표나 줄바꿈으로 구분합니다. 영문 대소문자를 구분하지 않는 부분 문자열 검색입니다. 정규식은 사용하지 않습니다.
4. 규칙을 저장합니다. 화살표로 우선순위를 바꿀 수 있습니다. 여러 규칙이 일치해도 위에서 처음 일치하는 규칙 하나만 적용합니다.
5. 조회 범위를 정하고 **미리보기 조회 → 분류 실행**을 누릅니다.

기본 조회 범위는 **최근 30일, 최신 100개**입니다. 최대 최근 365일, 최신 500개까지 설정할 수 있습니다.
범위는 수동·자동 실행에 동일하게 적용됩니다. 조회 범위 밖의 오래된 메일은 정리하지 않습니다.
최신 메일이 많으면 더 오래된 대상이 조회에 포함되지 않을 수 있으니 조회 한도를 조절하세요.
미리보기는 15분간 유효하며 규칙이나 설정 변경 시 무효화됩니다.

## 5. 스팸 키워드를 등록해 자동 이동

1. **분류 방식 → 스팸 → 정크 메일**을 선택합니다.
2. 예: `무료 당첨`, `불법 광고` 등 원하는 키워드를 등록합니다. 일반적인 업무 단어는 오분류될 수 있으니 구체적인 키워드를 사용하세요.
3. **규칙 저장**을 누르면 정크 메일을 목적지로 지정하고 자동 실행을 켭니다.
4. 다음 실행 주기부터 받은편지함에 있는 일치 메일을 Outlook 정크 메일 폴더로 이동합니다. 기본 간격은 15분이고 **자동으로 정리하기**에서 변경할 수 있습니다.

새 스팸 규칙은 목록 맨 위에 추가합니다. 원하면 우선순위를 조절할 수 있습니다.
자동 실행은 **스팸을 포함한 모든 활성 규칙**에 적용됩니다.
미리보기가 열려 있으면 먼저 **미리보기 닫기**를 눌러야 자동 실행이 진행됩니다.
스팸 저장 직후 결과를 보고 싶다면 **미리보기 조회 → 분류 실행**을 사용하세요.

정크 메일 폴더는 표시 언어에 관계없이 Microsoft Graph의 `junkemail` 폴더로 식별합니다.
이 기능은 정크 메일 폴더 이동이며, Microsoft의 스팸 필터 학습이나 스팸 신고 API를 호출하지 않습니다.

## 6. 중단 · 이어하기 · 되돌리기

- **중단 · 자동 실행 끄기**: 현재 전송 중인 요청 한 건을 마무리하고 멈춥니다. 다음 주기 자동 실행도 끕니다.
- **중단 지점부터 이어하기**: 남은 메일부터 처리합니다. 네트워크 오류로 결과가 불분명한 메일은 실제 폴더를 확인한 뒤 처리합니다.
- **현재 작업 되돌리기**: 이동 완료된 메일을 원래 폴더로 복구하고 미처리 메일은 그대로 둡니다. 복구 중에도 중단·이어하기가 가능합니다.
- **이전 작업 복구**: 현재 작업 외 최근 20개 작업을 보관합니다. 목록에서 이전 작업을 선택해 되돌릴 수 있습니다. 더 오래된 기록은 자동으로 정리됩니다.

메일이 다른 앱이나 Outlook 규칙에 의해 제3의 폴더로 옮겨지면 작업을 중단하고 알려줍니다.
분류 중에는 해당 메일을 원래 폴더로, 복구 중에는 분류 목적지 폴더로 돌려놓은 뒤 이어하기를 누르세요.
삭제된 메일, 없어진 폴더, 온라인 보관 사서함 이동 등은 자동 복구하지 못할 수 있습니다.
중단한 작업이 남아 있으면 규칙 변경과 새 작업을 제한합니다. 이어서 마무리하거나 현재 작업을 되돌려 주세요.

작업은 메일별로 저장하며, 서비스 워커가 다시 시작되면 기록과 실제 메일 위치를 확인합니다.
Chrome을 닫으면 예약 실행이 보장되지 않으며, 절전 상태의 알람은 지연될 수 있습니다.
토큰은 세션 저장소에만 보관하므로 Chrome 재시작 후 다시 로그인하세요. 로그인 만료 시 자동 실행은 꺼지거나 작업이 중단되며, 재연결 후 이어하기/자동 실행을 다시 설정할 수 있습니다.

## 지원 범위와 데이터

- Microsoft Graph를 지원하는 Microsoft 365 / Outlook.com의 **로그인한 본인 사서함**을 대상으로 합니다.
- Outlook 데스크톱 앱을 열어둘 필요는 없습니다. 확장 프로그램은 Chrome에서 실행됩니다.
- 온프레미스 Exchange, 공유 사서함, 로컬 PST는 이 버전에서 지원하지 않습니다.
- 규칙, 메일 제목·보낸 사람, 원래/목적지 폴더 ID와 처리 상태를 Chrome 로컬 저장소에 보관합니다.
- 실제 메일 본문은 조회·키워드 검사 동안 메모리에서만 사용합니다. 첨부파일은 조회하지 않습니다.
- 별도 서버, AI 서비스, 광고 또는 외부 분석 서비스로 데이터를 전송하지 않습니다. Microsoft 인증과 Graph만 호출합니다.
- 확장 프로그램 삭제 또는 **설정과 기록 초기화** 후에는 복구 기록을 사용할 수 없습니다. 이미 이동된 메일 자체는 그대로 남습니다.
- 계정 간 복구 기록 혼용을 막습니다. 다른 계정을 사용하려면 먼저 필요한 복구를 완료하고 기록을 초기화하세요.

## 검증과 개발

의존성 없이 Node.js에서 실행:

```powershell
node --test tests/core.test.js tests/worker.test.js
```

자동 테스트는 키워드 판정, 스팸 목적지, 미리보기 무변경, 이동과 복구, 응답 유실 후 중복 방지, 요청 도중 중단, 외부 폴더 변경 및 워커 재시작 후 결과 확인을 검사합니다.

`tests/ui-smoke.mjs`는 Playwright와 설치된 Chrome을 사용하는 화면 테스트입니다. Chrome API를 모형으로 제공하며 Microsoft 로그인이나 실제 Graph 서버 연결을 검증하지 않습니다.
첫 인수로 설치된 `playwright/index.mjs` 경로를 넘깁니다. Chrome 위치는 필요하면 `CHROME_PATH` 환경변수로 지정할 수 있습니다.
화면 점검을 직접 실행하면 결과가 `screenshots/`에 저장됩니다. 대표 화면은 `screenshot.png`에서 확인할 수 있습니다.

**검증 범위:** 9개 자동 테스트 및 Chrome 화면 조작 테스트를 통과했습니다. 실제 Chrome 확장 설치 환경에서의 Microsoft 로그인과 실제 사서함 이동은 사용자 앱 등록 및 로그인 후 확인이 필요합니다.

주요 파일: `manifest.json`(확장 설정), `dashboard.*` / `styles.css`(관리 화면), `core.js`(규칙), `background.js`(작업·기록·알람), `auth.js`(PKCE 로그인), `graph.js`(Outlook API).
