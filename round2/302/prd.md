# HRM 팀 소개 페이지 PRD

|---|---|
| 문서 상태 | 초안 v0.1 |

> PRD(Product Requirements Document)는 홈페이지를 누구를 위해, 왜, 어떤 내용으로 만들지 정리한 요구사항 문서입니다. 이 문서의 회사와 연락처는 모두 연습용 가상 정보입니다.

## 한 줄 소개

HRM은 채용과 교육을 비롯한 인사 업무를 맡고, 새로운 동료의 시작과 구성원의 성장을 돕는 팀입니다.

## 1. 배경 · 문제

- 신규 입사자와 채용 지원자가 회사의 전반적인 모습과 HRM 팀의 역할을 한곳에서 파악하기 어렵다. (가정)
- 한 장의 소개 페이지에서 회사, 팀, 주요 업무, 채용·교육 안내를 차례로 보여 준다.

## 2. 목표와 성공 기준

| 목표 | 성공 기준 (측정 방법) |
|---|---|
| 방문자가 회사와 HRM 팀의 역할을 이해한다 | 신규 입사자·지원자 역할의 검토자 3명에게 페이지를 보여 주고 각자 회사 업종과 HRM 업무 3가지를 말할 수 있는지 확인 (가정) |
| 필요한 안내를 쉽게 찾는다 | 검토자가 채용 또는 교육 안내와 문의 위치를 30초 안에 찾는지 확인 (가정) |

## 3. 대상 사용자

| 대상 | 궁금한 것 | 페이지가 줘야 할 답 | 기대 행동 |
|---|---|---|---|
| 신규 입사자 | 회사는 무엇을 하고, HRM은 무엇을 지원하는가? | 가상 IT 회사 개요, HRM 역할, 교육·적응 지원 | 필요한 안내를 읽고 예시 문의 경로를 확인한다 |
| 채용 지원자 | 회사와 HRM 팀은 어떤 곳인가? | 회사 소개, 채용 과정의 개괄, HRM 주요 업무 | 팀과 회사에 대한 기본 정보를 파악한다 |

## 4. 범위

**이번에 만드는 것**
- 한 장짜리 회사·HRM 팀 소개 페이지
- 회사 소개, HRM 소개, 6개 업무 카드, 채용·교육 안내, 문의 섹션
- 데스크톱·휴대폰 대응, 섹션 이동 메뉴

**이번에 만들지 않는 것**
- 실제 채용 공고, 지원서 제출, 로그인, 게시판, 서버로 전송하는 문의 폼
- 실제 회사 정보, 직원 실명, 실제 연락처

## 5. 정보 구조 (메뉴)

|---|---|---|
| 회사 소개 | `#company` | 가상 IT 회사 소개와 핵심 가치 (가정) |

| 채용·교육 | `#programs` | 채용·교육의 개괄과 준비 중 안내 |

## 7. 콘텐츠 상세

### 7-1. 회사와 팀 소개
- 가상 회사 이름: 하늘테크 (가정)
- 회사 소개: “사람과 기술을 연결하는 IT 서비스를 만드는 회사” (가정)
- 팀 제목: “사람의 시작과 성장을 함께하는 HRM” (가정)
- 보조 문구: “HRM은 약 9명 규모로, 채용과 교육을 비롯한 인사 업무를 담당합니다.”
- 주요 버튼: “HRM이 하는 일 보기”, “채용·교육 알아보기”

### 7-2. 업무 카드

| # | 제목 | 설명 (2줄 이내) |
|---|---|---|
| 1 | 채용 | 필요한 동료를 만나는 과정을 기획하고 지원합니다. |
| 2 | 신규 입사자 지원 | 새로운 동료가 회사에 적응하도록 입사 초기 경험을 돕습니다. |
| 3 | 교육 | 구성원의 성장에 필요한 학습 기회를 기획합니다. |
| 4 | 인사평가 | 공정하고 이해하기 쉬운 평가 운영을 지원합니다. |
| 5 | 복리후생 | 구성원이 안정적으로 일할 수 있는 제도를 안내하고 운영합니다. |
| 6 | 인사제도 | 일하는 방식에 맞는 인사 기준과 제도를 정리합니다. |

### 7-3. 채용·교육 안내
- 채용: 지원자가 회사와 직무를 알아볼 수 있도록 채용 절차의 개요를 소개한다. 구체적인 단계와 일정은 미정이므로 만들지 않는다. (가정)
- 교육: 신규 입사자 적응과 구성원 성장을 위한 교육을 소개한다. 실제 프로그램과 일정은 “준비 중”으로 표시한다. (가정)

### 7-4. 문의

| 항목 | 값 |
|---|---|
| 문의 채널 | `#hrm-문의` (예시) |
| 이메일 | `team@example.com` (예시) |
| 응답 시간 | 미정. 페이지에는 약속 문구를 넣지 않음 |

## 8. 디자인 가이드

상세 구현값은 `style-guide.md`를 따른다. 원래 제안한 하늘색 디자인은 사용자가 제공한 Forest and Sage 스타일로 변경했다. HRM의 전문성과 사람 중심의 친근함을 숲색의 명도 대비, 부드러운 녹색, 넉넉한 곡선으로 표현한다.

| 항목 | 값 |
|---|---|
| 메인 색 | Forest `#01472e` |
| 보조 색 | Sage `#ccd5ae`, Olive `#e9edc9`, Cream `#fefae0`, Moss `#a3b18a` |
| 느낌 | 깔끔한 / 단정한 / 친근한, 자연스러운 질감과 강한 대비 |
| 글꼴 | 큰 영문 제목은 Anton, 본문·버튼·한글은 Inter와 시스템 한글 대체 글꼴 |
| 모서리 · 그림자 | 큰 영역 `5rem`, 카드 `2.5rem`; Forest 색이 도는 부드러운 그림자 |
| 질감 | 전체 화면에 고정된 SVG 노이즈, 불투명도 0.04 |
| 움직임 | 아래에서 위로 드러나는 1.2초 리빌, 장식 요소의 은은한 부유 애니메이션. 움직임 줄이기 설정을 존중 |
| 로고 | `images/logo.png`가 있으면 사용, 없으면 HRM 글자 임시 로고 |
| 참고 이미지 | 없음 |

## 9. 반응형 · 접근성

- 휴대폰 375px부터 데스크톱 1280px까지 가로 스크롤이 생기지 않는다.
- 업무 카드는 데스크톱 3열, 태블릿 2열, 휴대폰 1열로 배치한다.
- 640px 아래에서는 햄버거 메뉴를 제공한다.
- 버튼은 키보드로 사용할 수 있고, 텍스트와 배경의 대비를 확보한다.
- 장식이 아닌 이미지에는 대체 텍스트를 넣는다.

## 10. 기술 조건

- `index.html` 한 파일에 HTML·CSS·필요한 JavaScript를 넣는다.
- 빌드 도구 없이 파일을 더블클릭해 열 수 있어야 한다.
- 외부 의존은 선택적 Anton·Inter 글꼴 CDN 정도로 제한한다.

## 13. 열린 질문

- 가상 회사 이름 “하늘테크”를 유지할지, 다른 가상 이름으로 바꿀지
- 채용·교육의 실제 세부 내용이 준비되면 어떤 항목을 공개할지
- 문의 채널과 이메일을 공개할 필요가 생기면 어떤 값으로 교체할지
- 가상 회사와 팀을 공개할 실제 페이지로 전환할 때 디자인 표현을 유지할지
