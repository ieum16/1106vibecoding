# 갈피 웹서비스 PRD

## 한 줄 소개
문서 작업의 부담을 덜어 사용자가 잠시 쉬어갈 수 있도록 돕는 5명 팀의 문서 작업 페이지.

## 제출 버전과 향후 계획
배포 주소: https://galpiweb1106-2wk5.vercel.app/

현재 제출 버전은 정적 홈페이지입니다. 문서 유형 선택, 요청 입력, 기본 구조의 초안 생성, 직접 수정, TXT 저장, 브라우저 인쇄를 통한 PDF 저장을 지원합니다. AI 분석·재작성, 회사 템플릿 적용, Word/PPTX 출력, 서버 공유 링크는 아직 미구현입니다.

아래 원래 PRD의 AI·서버·공유 관련 내용과 완료 기준은 향후 제품 확장 계획입니다. 디자인은 최신 사용자 결정에 따라 전체 UI를 Noto Serif KR 명조체로 통일했습니다. 종이색·먹색과 확정 로고를 유지합니다.

PRD는 무엇을 누구를 위해 왜 만드는지 정리한 제품 요구사항 문서입니다.

## 1. 배경 · 문제
공식 문서를 작성해야 하지만 시간이 부족하거나 작성 과정이 번거로운 사내 직원이 대상이다. 흩어진 프로젝트 내용과 참고 자료를 목적에 맞는 문서로 정리하고 회사 양식을 적용하는 부담을 줄인다.
브랜드의 의미: 책갈피를 꽂고 쉬듯, 사용자가 문서 작업을 맡겨두고 잠시 쉴 수 있게 한다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 |
|---|---|
| 요청부터 결과 수령까지 한 흐름으로 제공 | 내용 입력 → 생성 → 미리보기 → 다운로드 완료 |
| 실제로 열리는 문서 제공 | Word와 PDF를 열어 한국어·표·페이지 구성을 확인 |
| 공유 링크로 결과 전달 | 다른 브라우저에서 허용된 결과를 열고, 만료·철회 시 접근 불가 |
| 입력과 목적에 맞는 내용 | 원문에 없는 사실은 만들지 않고 부족한 항목은 확인 필요로 표시 |

## 3. 대상 사용자
문서 작업을 요청할 사내 직원. 문서 종류를 확인하고 원본 내용·목적·양식 등을 제출하여 결과물을 받는다.

## 4. 범위
### 이번 제품의 필수 기능
- 웹 운영 매뉴얼, 프로젝트 정리, 인수인계서, 보고서, 발표 자료 유형 안내.
- 내용·목적·독자·문서 종류·출력 형식을 입력하는 요청서.
- 선택적으로 회사 템플릿과 로고를 첨부.
- AI 문서 초안 생성, 미리보기, 수정 요청, Word(.docx)·PDF 다운로드.
- 결과에 대한 공유 링크 생성·복사·철회. 비공개 기본값과 만료 시간 제공 (가정).
- 진행 상태·오류·재시도 표시. 실패했을 때 완료로 표시하지 않는다.
### 이후 확장
- PPTX 출력. 초기에는 발표용 원고·구성안을 Word/PDF로 제공한다고 명시 (가정).
- 복잡한 서식·매크로·모든 원본 레이아웃의 완전 보존은 지원 형식을 정한 뒤 별도 검증.

## 5. 정보 구조
첫 화면 문서 생성 / 팀 소개 / 제작 가능한 문서 / 의뢰 방법 / FAQ / 제작 의뢰.

## 6. 화면 구성
헤더(로고·메뉴) → 제목·내용 입력창 → 문서 종류·형식·첨부·생성 버튼 → 생성 상태 → 결과 미리보기·수정·다운로드·공유 → 문서 유형 안내 → 의뢰 방법 → 팀 소개(5명) → FAQ → 푸터.
팀 소개보다 문서 생성 도구가 먼저 보이게 한다. 모바일에는 위에서 아래로 배치한다.

## 7. 콘텐츠 상세
- 로고 문구: 문서는 갈피에게, 당신은 잠시 쉼.
- 메인 제목: 문서 작업은 갈피에게. 당신은 잠시 쉬어가세요. (가정)
- 설명: 내용과 목적을 알려주시면, 필요한 양식의 문서로 정리해 드립니다.
- 주요 버튼: 문서 만들기 / 예시로 시작하기 / Word 다운로드 / PDF 다운로드 / 공유 링크 만들기.
- 문서 유형: 웹 운영 매뉴얼(운영 절차), 프로젝트 정리(배경·진행·결과), 인수인계서(담당 업무·현황·후속 조치), 보고서(요약·분석·제언), 발표 원고(슬라이드 구성·발표 흐름).
- 요청 항목: 문서 종류, 제목, 목적, 독자, 원문, 출력 형식, 선택 첨부, 추가 요청.
- 지원 확장자·용량은 첨부 선택 전에 표시. 실제 값은 기술 검증 후 확정.
- 빈 내용, 처리 실패, 미지원 첨부는 다음 행동이 보이는 오류로 안내.
- 공유 전에 사용자가 결과를 검토하도록 한다.

## 9. 반응형 · 접근성
375px와 데스크톱에서 가로 스크롤 없이 동작. 입력에 라벨 제공, 키보드 접근·포커스 표시, 생성 상태 안내. 흐린 글자색은 필수 본문에 쓰지 않고 대비를 검증한다. 작은 화면에는 읽을 수 있는 크기로 조정한다.

## 10. 기술 조건
정적 index.html만으로 실제 AI 생성·첨부 해석·파일 변환·공유 저장을 모두 제공할 수 없다. 제품 구현은 프런트엔드 + 서버 + 문서 변환 + 저장소가 필요하다. 모델 자격 증명은 서버에만 둔다. 선택한 AI 공급자와 저장소는 미정이다.
데모를 만들 경우 생성·공유 모의 동작임을 명확히 표시하며 실제 기능 완료와 구분한다. 로컬 주소를 외부 공유 링크로 안내하지 않는다.

## 11. 일정
기획·로고 확정 → 화면 제작·동작 검토 → AI·문서 출력 연결 → 공유 저장·접근 연결 → 종합 검증. 소요 시간은 기술 검토 후 결정.
