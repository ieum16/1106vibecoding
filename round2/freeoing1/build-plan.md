# 아이작 팀 홈페이지 제작 계획서

## 1. 만들 것
- prd.md에 맞춘 한 장짜리 팀 소개 홈페이지 index.html.
- 기존 고객에게는 장애 접수 안내, 새 고객에게는 자동화 서비스 문의 안내를 제공한다.
- 실제 장애 전송·고객 알림은 외부 연결 후 구현하는 다음 단계이다. 초기 버전에서는 연결 준비 상태를 알린다(가정).
- 기획서 확인과 제작 요청을 받은 뒤 홈페이지를 만든다.

## 2. 파일 구조
| 경로 | 역할 | 상태 |
|---|---|---|
| team-page/prd.md | 홈페이지 기획서 | 작성 |
| team-page/logo-prompt.md | 로고 제작 프롬프트 | 작성 |
| team-page/build-plan.md | 구현·검토 순서 | 작성 |
| team-page/index.html | 실제 홈페이지 | 제작 확인 후 작성 |
| team-page/images/logo.png | 확정 로고 | 미제공 |
| team-page/images/reference.png | 참고 화면 | 선택 사항, 미제공 |

## 3. 준비물 체크
| 준비물 | 상태 | 없을 때 |
|---|---|---|
| 로고 | 아직 없음(가정) | ‘아’ 글자 임시 로고 사용 |
| 참고 이미지 | 미제공 | 모노크롬·레드 디자인 적용 |
| 실제 접수 폼 주소 | 미정 | 실제 전송되지 않는 ‘준비 중’ 안내 |
| 문의 채널 | 미정 | 예시 주소와 운영 연결 준비 안내 |
| 공개용 실적·도구 | 미제공 | 임의 실적 대신 ‘준비 중’ 카드 |

## 4. 만드는 순서
| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| 1 | 기획서 검토와 제작 확인 | 로고 유무, 시연용 접수 범위 |
| 2 | 헤더·소개·서비스·도구·접수·문의·푸터 구성 | 메뉴와 섹션 연결 |
| 3 | 색·글꼴·여백·카드 스타일 적용 | 검정·흰색·빨강 #ef4444 적용 |
| 4 | 첫 화면과 두 가지 주요 버튼 | 고객 목적에 따라 안내를 찾을 수 있음 |
| 5 | 서비스 3개 카드와 요청 예시 | 확정한 서비스와 일치 |
| 6 | 준비 중 도구 카드 | 미구현 상태를 정확히 표시 |
| 7 | 장애 접수·문의 안내 | 실제 수신·전송되는 것처럼 표현하지 않음 |
| 8 | 모바일과 키보드 조작 | 375px 화면·포커스·메뉴 열고 닫기 |
| 9 | 최종 검토 | PRD 완료 기준 확인, 실제 실행 여부 구분 |

## 5. 섹션별 구현 메모
| 섹션 | 레이아웃 | 데스크톱 → 휴대폰 |
|---|---|---|
| 헤더 | 로고 왼쪽, 4개 메뉴 오른쪽 | 고정 메뉴 → 햄버거 |
| 소개 | 큰 제목, 설명, 주요 버튼 2개 | 넓은 구성 → 세로 배치 |
| 서비스 | 카드 3개 | 3열 → 2열 → 1열 |
| 도구 | 점선 준비 중 카드 | 넓은 카드 → 1열 |
| 장애 접수 | 필요한 정보와 접수 상태 | 2열 → 1열 |
| 문의 | 검정 배경·흰색 글자의 상담 안내 | 2열 → 1열 |

## 6. 모노크롬·레드 스타일 구현
- 검정·아연색·흰색 중심으로 구간을 나누고 빨강 #ef4444만 강조색으로 사용한다.
- ZTNature 파일이 없어 local 글꼴을 우선 선언하고 Inter와 한글 대체 글꼴을 사용한다.
- 렌즈 느낌의 그래픽은 CSS 그라데이션으로 제작한다.
- 스크롤 진행도에 따라 배경을 1.27까지 확대하고 제목을 .89까지 축소한다.
- 등장 모션에 cubic-bezier(.16,1,.3,1)를 적용한다.
- 움직임 정지와 시스템 동작 줄이기를 지원한다.
- 서비스 상세는 details/summary로, 준비 양식은 dialog로 구현한다.
- 양식 입력은 메모리에서만 유지하고 닫을 때 비운다. 실제 전송 성공 메시지는 표시하지 않는다.

## 7. 확인 방법
- HTML 문서의 언어, 제목, 상대 이미지 경로를 확인한다.
- 모노크롬 반전 구간, 큰 제목과 얇은 이탤릭 조합이 명세와 맞는지 확인한다.
- 움직임 멈추기 버튼과 시스템 동작 줄이기 설정에서 스크롤 확대·축소이 멈추는지 확인한다.
- 모바일에서 영문 대형 제목과 넓은 여백가 화면 밖으로 넘치지 않는지 확인한다.
- 브라우저에서 데스크톱과 375px 화면을 확인한다.
- 상단 메뉴, 장애 접수 안내 버튼, 자동화 문의 버튼을 누른다.
- 모바일 메뉴가 열리고 닫히며 항목 선택 후 접히는지 확인한다.
- 키보드로 메뉴와 버튼에 접근하고 포커스가 보이는지 확인한다.
- 이미지가 없어도 임시 로고가 보이고 화면이 깨지지 않는지 확인한다.
- 접수되지 않았는데 접수 완료로 표시하는 동작이 없는지 확인한다.
- 브라우저 확인이 불가능하면 실행 검증을 했다고 주장하지 않고 직접 열어볼 방법을 안내한다.

## 8. 만든 뒤 고치기 예시
- 서비스 카드에 다른 자동화 항목을 추가해 줘.
- 로고 파일을 넣었으니 임시 로고를 바꿔 줘.
- 준비한 실제 접수 폼 링크를 연결해 줘.
- 첫 화면에 장애 접수 버튼을 더 크게 보여 줘.

## 10. 실제 확인 결과
- 데스크톱 첫 화면과 가로 넘침 없음 확인.
- 장애 전달 및 문의 준비 대화상자 확인.
- 장애 전달 내용 복사 성공 메시지 확인.
