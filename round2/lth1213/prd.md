# bell 팀 소개 페이지 PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | v0.3 · Meadow-glass ledger 적용 |
| 작성일 | 2026-11-06 |
| 작성자 | bell 팀 |
| 관련 문서 | logo-prompt.md, build-plan.md |

> PRD는 무엇을, 누구를 위해, 왜 만드는지 정리한 제품 요구사항 문서입니다. bell은 연습용 가상 팀으로 설정합니다(가정).

## 1. 배경 · 문제
- 외부 파트너가 bell 팀의 역할과 협업 가능한 분야를 한눈에 이해할 소개 공간이 필요하다.
- 신사업 발굴과 업무 자동화라는 두 역량을 구체적인 업무와 요청 예시로 연결한다.
- 기존 소개 채널과 문의 현황은 확인되지 않았다. 현재 문제가 수치로 검증되었다고 표현하지 않는다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 (측정 방법) |
|---|---|
| 외부 파트너가 팀의 역할을 이해한다 | 검토자 3명 중 3명이 1분 안에 신사업 발굴과 업무 자동화 역량을 설명한다(가정) |
| 협업 요청 방법을 쉽게 찾는다 | 검토자 3명 모두 메인 버튼으로 문의 섹션에 도달한다(가정) |
| 적절한 협업 제안을 돕는다 | 문의 영역에서 제안에 필요한 정보 3개를 확인할 수 있다 |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줘야 할 답 | 기대 행동 |
|---|---|---|---|
| 외부 파트너 | 어떤 팀이며 무엇을 함께할 수 있는가? | 역할, 업무 4개, 협업 분야, 요청 방법 | 역할을 이해하고 협업을 요청한다 |

## 4. 범위
**이번에 만드는 것**
- 반응형 단일 소개 페이지, 업무 카드 4개, 협업 분야, 도구 준비 중 카드, 문의 안내.
- 로고 제작 프롬프트와 디자인 가이드.

**이번 범위 밖**
- 로그인, 게시판, 서버에 전송하는 문의 폼, 분석 도구, 실제 이메일 발송.
- 확인되지 않은 실적·고객사·파트너사·성과 수치.

## 5. 정보 구조 (메뉴)
| 메뉴 | 섹션 ID | 담는 내용 |
|---|---|---|
| 팀 소개 | #intro | 팀 정의, 핵심 가치, 협업 요청 버튼 |
| 하는 일 | #work | 신사업 기회 조사, 사업 아이디어 검증, 업무 자동화, 맞춤형 도구 제작 |
| 협업 분야 | #collaboration | 함께할 수 있는 과제와 협업 흐름 |
| 우리가 만든 도구 | #tools | 준비 중 카드 |
| 문의 | #contact | 협업 제안 안내, 예시 이메일 |

## 6. 화면 구성 (위에서 아래로)
```
고정 헤더: 골든벨 로고 + bell + 메뉴
① 팀 소개: 한 줄 소개 / 보조 문구 / 협업 제안하기
② 하는 일: 업무 카드 4개
③ 협업 분야: 과제 예시 + 제안 → 검토 → 작은 실험 흐름
④ 우리가 만든 도구: 준비 중 카드
⑤ 문의: 제안 시 필요한 정보 + 예시 이메일
푸터: bell 팀 / 연습용 페이지 안내
```
협업 흐름은 제안용 구성이다(가정). 실제 운영 절차로 확정된 표현은 사용하지 않는다.

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 제목: 새로운 사업의 가능성을 찾고, 반복되는 일을 바꿉니다.
- 팀 정의: bell은 신사업을 발굴하고 반복 업무를 자동화 도구로 바꾸는 팀입니다.
- 보조 문구: 아이디어의 가능성을 살피고, 일상의 비효율을 실용적인 도구로 풀어갑니다. 함께 시작할 과제를 제안해 주세요.
- 버튼: 협업 제안하기 → #contact / 하는 일 살펴보기 → #work.

### 7-2. 업무 카드
| # | 제목 | 설명 | 요청 예시 |
|---|---|---|---|
| 1 | 신사업 기회 조사 | 시장과 사용자 문제를 살피고 새로운 사업 기회를 찾습니다. | 새로운 시장의 가능성을 함께 살펴보고 싶어요. |
| 2 | 사업 아이디어 검증 | 핵심 가설을 정리하고 작은 실험으로 가능성을 확인합니다. | 아이디어를 작은 실험으로 검증하고 싶어요. |
| 3 | 업무 자동화 | 반복되는 업무 흐름을 정리하고 자동화 방법을 설계합니다. | 반복적인 자료 정리 업무를 줄이고 싶어요. |
| 4 | 맞춤형 도구 제작 | 실제 업무에 필요한 기능을 작은 도구로 구체화합니다. | 우리 업무 방식에 맞는 도구가 필요해요. |

### 7-3. 협업 분야
- 신사업 탐색: 해결할 문제와 기회를 함께 정의하는 과제.
- 아이디어 실험: 가설과 검증 방법을 구체화하는 과제.
- 업무 개선: 반복 과정과 도구 수요를 함께 살펴보는 과제.
- 위 항목은 업무 역량에 근거한 제안이다(가정). 성과나 납기를 보장하지 않는다.

### 7-4. 도구와 문의
- 공개 도구가 확인되지 않아 점선 카드에 ‘준비 중’을 표시한다. 작동하지 않는 체험 버튼은 만들지 않는다.
- 문의 시 알려 줄 정보: 해결하려는 문제 / 원하는 변화 / 함께하고 싶은 방식.

| 항목 | 값 |
|---|---|
| 이메일 | team@example.com · 예시 주소, 실제 문의 접수용 아님 |
| 요청 채널 | 이메일 안내만 표시(가정) |
| 응답 시간 | 미정 · 응답 기한을 약속하지 않음 |

## 8. 디자인 가이드
| 항목 | 값 |
|---|---|
| 메인 색 | 라임 #9FE870 |
| 보조 색 | 밝은 회색 #F0F0F0, #ECF9F9 |
| 포인트 색 | 숲색 #163300 |
| 본문 색 | #0E0F0C / 흰 배경 #FFFFFF |
| 느낌 | 차분한 / 믿음직한 / 여백 많은 |
| 글꼴 | 제목 Wise Sans → Arial Black → 한국어 굵은 시스템 글꼴 / 본문 Inter → 한국어 시스템 글꼴 |
| 모서리 · 그림자 | 기능 카드 30px · 캡슐형 버튼 · 그림자 대신 가는 경계선 |
| 로고 | images/logo.png · 금색 종 모티프 + 숲색 소문자 bell |
| 참고 이미지 | 없음 · PRD 디자인 가이드를 따름 |

로고 추천: 둥근 금색 종, 작은 울림 선 2개, 남색 소문자 bell. 새로운 기회를 알리고 업무의 변화를 시작한다는 의미를 담는다. 종 모양을 단순화하고 글로우·금속 질감·복잡한 장식을 피한다. 골드는 장식에 쓰고, 작은 본문 글자는 #23221F 또는 딥 틸로 대비를 확보한다.

## 9. 반응형 · 접근성
- 375px 휴대폰부터 1280px 데스크톱까지 가로 스크롤이 없어야 한다.
- 업무 카드: 데스크톱 2열 → 태블릿 2열 → 휴대폰 1열.
- 768px 미만에서 햄버거 메뉴, 휴대폰 좌우 여백 16px.
- 키보드 조작, 보이는 포커스, 메뉴 열림 상태, 이미지 대체 텍스트를 제공한다.
- 일반 텍스트 대비 4.5:1 이상을 목표로 확인한다. 동작 줄이기 설정을 존중한다.
- 고정 헤더에 섹션 제목이 가려지지 않도록 스크롤 여백을 둔다.

## 10. 기술 조건
- index.html 하나에 CSS·JS 포함, 빌드 도구 없이 더블클릭으로 연다.
- 외부 의존은 글꼴 CDN 정도로 제한하고 시스템 글꼴 대체를 제공한다.
- 로고 파일이 없으면 B 글자를 넣은 인라인 SVG로 임시 로고를 표시한다. 나중에 images/logo.png를 넣으면 자동으로 교체되도록 구현한다.
- 문의 영역에는 예시 주소임을 명시한다. 전송 완료나 접수 성공을 표시하지 않는다.

## 14. 디자인 변경 · 2026-11-06
- 사용자 제공 teal-ledger-corporate-design.md를 시각 디자인 기준으로 적용했다.
- 기존 남색·골드 중심 방향을 청록 히어로, 흰색·연회색 밴드, 각진 카드, 가는 구분선, 딥 틸 캡슐 CTA로 변경했다.

- 첨부 문서의 사진·로고 마퀴·사례 슬라이더는 해당 콘텐츠가 없으므로 추가하지 않는다. 기존에 합의한 5개 섹션과 업무를 유지한다.
