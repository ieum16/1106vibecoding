> PRD(Product Requirements Document)는 무엇을, 누구를 위해, 왜 만드는지 정리한 문서입니다.

## 한 줄 소개
동네 주민에게 오늘의 안전 활동과 봉사 소식을 전하고, 불편 신고 안내를 확인할 수 있는 떡잎방범대 소개 페이지입니다.

## 1. 배경 · 문제
동네 주민들이 떡잎방범대가 어떤 안전 활동과 봉사를 했는지 확인할 수 있는 창구가 필요하다. 주민이 생활 속 불편 사항을 팀에 전달할 수 있는 신고 안내도 함께 제공한다. 현재 활동 일정과 신고 접수 방식은 정해지지 않아 실제 게시·접수 기능은 추후 연결이 필요하다. (가정)

## 2. 목표와 성공 기준
| 목표 | 성공 기준 (측정 방법) |
|---|---|
| 주민이 팀의 역할을 쉽게 이해한다 | 첫 화면에서 팀 이름과 동네 안전 활동을 바로 확인할 수 있다 |
| 주민이 오늘의 활동과 봉사를 확인한다 | 각각의 섹션에서 날짜와 활동 내용을 읽을 수 있다 |
| 주민이 불편 신고 방법을 찾는다 | 신고 섹션에서 안내와 접수 방법을 쉽게 찾는다 |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줘야 할 답 | 기대 행동 |
|---|---|---|---|
| 동네 주민 | 오늘 어떤 보안 활동과 봉사를 했는지 | 오늘의 활동·오늘의 봉사 내역 | 활동 내용을 확인하고 필요한 경우 불편 신고 안내를 이용 |
| 동네 주민 | 불편 사항을 어떻게 알리는지 | 신고할 내용과 접수 경로 | 안전에 관한 불편 사항 전달 |

## 4. 범위
**이번에 만드는 것 (In scope)**
- 팀과 활동을 소개하는 단일 페이지
- 오늘의 활동, 오늘의 봉사, 불편 신고, 대원 소개 섹션
- 보내 주신 로고 이미지 반영
- 모바일 대응 화면

**이번에 안 만드는 것 (Out of scope)**
- 서버에 저장되는 신고 접수, 로그인, 관리자 대시보드, 실시간 게시판
- 실제 대원 개인정보나 실제 연락처 노출

## 5. 정보 구조 (메뉴)
| 메뉴 | 섹션 ID | 담는 내용 |
|---|---|---|
| 오늘의 활동 | `#activities` | 오늘의 동네 안전·순찰 활동 (예시 콘텐츠로 표시) |
| 오늘의 봉사 | `#volunteer` | 오늘의 봉사 내역 (예시 콘텐츠로 표시) |
| 불편 신고 | `#report` | 신고 안내와 접수 방식. 실제 연결 전에는 데모임을 표시 |
| 대원 소개 | `#members` | 5명 대원 소개. 실명 대신 별칭 또는 역할 사용 |

## 6. 화면 구성 (위에서 아래로)
```text
[고정 헤더: 로고 + 떡잎방범대 + 메뉴]
① 첫 화면 — 동네 안전을 함께 지키는 팀 소개 + 오늘 활동 섹션으로 이동 버튼
② 오늘의 활동 — 날짜와 활동 카드
③ 오늘의 봉사 — 날짜와 봉사 카드
④ 불편 신고 — 신고 안내와 입력 UI (실제 전송 기능은 연결 전)
⑤ 대원 소개 — 5명, 별칭/역할 중심
[푸터: 떡잎유치원 소속 · 팀 소개]
```

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 제목: 우리 동네 안전, 떡잎방범대가 함께 지켜요!
- 보조 문구: 오늘의 안전 활동과 봉사 소식을 확인하고, 동네의 불편 사항을 알려 주세요. (가정)
- 버튼: 오늘 활동 보기 / 불편 신고 안내

### 7-2. 오늘의 활동 및 봉사
| # | 제목 | 설명 | 요청 예시 |
|---|---|---|---|
| 1 | 오늘의 활동 | 실제 활동 정보가 제공되지 않아 제작 시 예시임을 표시한 샘플 카드 사용 (가정) | 실제 활동 내용을 알려 주시면 교체 |
| 2 | 오늘의 봉사 | 실제 봉사 정보가 제공되지 않아 제작 시 예시임을 표시한 샘플 카드 사용 (가정) | 실제 봉사 내용을 알려 주시면 교체 |

### 7-3. 불편 신고
| 항목 | 값 |
|---|---|
| 입력 항목 | 불편 내용, 위치(선택), 연락 방법(선택) (가정) |
| 접수 방식 | 실제 접수처 미정. 정적 페이지에서는 전송되지 않음을 명확히 표시 |
| 개인정보 | 민감한 개인정보를 입력하지 말라는 안내 표시 |

### 7-4. 대원 소개
- 대원 5명 소개 카드에 사용자가 알려 준 이름과 특징을 표시한다.
- 대원 이름과 특징: 짱구(골목길 돌아다니기), 철수(꼼꼼하게 쓰레기 줍기), 유리(나쁜 사람 혼내주기), 맹구(길가에 돌 치우기), 훈이(무서운 사람 만나면 울기).

## 8. 디자인 가이드
| 항목 | 값 |
|---|---|
| 메인 색 | 핑크 `#F47FA8` (가정, 밝고 읽기 쉬운 색으로 조정) |
| 보조 색 | 연분홍 `#FFF0F5` (가정) |
| 포인트 색 | 로고의 하늘색 `#4CC3E0`, 노란색 `#FFE43B`를 참고해 사용 |
| 느낌 | 활발한 / 아기자기한 / 장난스러운 |
| 글꼴 | Pretendard (없으면 시스템 기본) |
| 모서리 · 그림자 | 버튼은 알약형, 카드·입력은 적당히 둥글고 얇은 테두리, 그림자는 최소화 (가정) |
| 로고 | `images/logo.png` (사용자 제공 이미지) |
| 참고 이미지 | `images/reference.png` (사용자 제공 애니메이션 이미지, 활기찬 단체 분위기 참고) |
| 디자인 참고 | `references/design-direction.md` (Ollama 사이트 분석을 팀 성격에 맞게 조정) |

애니메이션 참고 이미지에서는 밝은 색감과 여러 대원이 함께 있는 활기찬 구성을 참고한다. 원본 장면이나 캐릭터를 그대로 재현하지 않고 친근한 팀 분위기만 반영한다. 메인 색은 핑크로 유지한다.

Ollama 참고에서 가져온 것은 흰 바탕, 여백, 단순한 타이포그래피, 둥근 버튼, 얇은 테두리, 절제된 장식이다. 흑백 중심 색상과 터미널 예시는 적용하지 않는다. 핑크 메인 색과 로고의 하늘색·노란색 포인트, 친근하고 장난스러운 콘텐츠를 유지한다. 세부 디자인 규칙은 `references/design-direction.md`에 정리했다.

## 9. 반응형 · 접근성
- 휴대폰(375px)부터 데스크톱(1280px)까지 가로 스크롤 없이 표시한다.
- 카드 그리드는 데스크톱 3열, 태블릿 2열, 휴대폰 1열로 구성한다.
- 휴대폰에서는 메뉴를 햄버거 버튼으로 표시한다.
- 충분한 글자 대비와 이미지 대체 텍스트를 적용한다.

## 10. 기술 조건
- `index.html` 하나에 CSS·JavaScript를 포함하고 빌드 도구 없이 연다.
- 신고 폼은 백엔드 연결 전까지 실제 전송하지 않으며, 접수 완료처럼 오해할 표현을 쓰지 않는다.
- 외부 의존은 글꼴 CDN 정도로 최소화한다.

## 12. 완료 기준
- [ ] 메뉴가 각 섹션으로 이동한다.
- [ ] 오늘의 활동·오늘의 봉사·불편 신고·대원 소개 순서로 구성된다.
- [ ] 375px 화면에서 가로 스크롤이 없다.
- [ ] 보내 준 로고가 헤더와 첫 화면에 자연스럽게 보인다.
- [ ] 실제 정보가 아닌 샘플 콘텐츠에는 예시임을 표시한다.
- [ ] 신고가 실제 접수되지 않는다는 점이 명확하다.

## 13. 열린 질문
- 참고 이미지의 활기찬 단체 분위기를 디자인에 반영하는 방향으로 정리함.
- 오늘의 활동과 오늘의 봉사에 사용할 실제 내용 및 날짜는 무엇인가?
- 불편 신고를 실제로 받을 연락처나 채널은 무엇인가? (현재는 임의로 만들지 않음)
- 대원 이름과 특징은 사용자에게 받아 반영함: 짱구, 철수, 유리, 맹구, 훈이.
- 신고 폼을 실제 전송하는 기능이 필요한가? 필요하다면 접수 서비스·관리 방식이 정해져야 한다.
