# 추적자 — Location Tracker 제작 계획서

## 1. 만들 것
`prd.md`에 정의한 주소 검색 도구입니다. 한 화면에서 검색 결과, 지도 핀, 좌표, 도로명·지번 주소를 확인하고 가상 담당자를 열어 봅니다. 사용자의 제작 요청에 따라 `index.html`과 로컬 실행 서버를 구현했습니다. 첨부 템플릿의 큰 영문 제목, 둥근 버튼과 검색창, 얇은 구분선과 평면 패널을 적용했습니다.

## 2. 파일 구조
```text
team-page/
├─ prd.md
├─ logo-prompt.md
├─ build-plan.md
├─ index.html          ← 구현 완료
├─ README.md           ← 실행·지도 연결 방법
├─ serve.cjs           ← 로컬 HTTP 서버
├─ browser-check.cjs   ← 브라우저 동작 검증
├─ DESIGN-reference.md ← 사용자가 제공한 디자인 참고 원문
└─ images/             ← 이미지가 준비되면 생성
   ├─ logo.png         ← 선택
   └─ reference.png    ← 선택
```

## 3. 준비물 체크
| 준비물 | 현재 상태 | 진행 방법 |
|---|---|---|
| 로고 | 이미지 없음, 영문 이름 확정 | Location Tracker 임시 글자 로고로 시작 가능 |
| 참고 디자인 | 사용자 제공 텍스트 문서 | DESIGN-reference.md와 PRD의 남색을 결합 |
| 담당자 데이터 | 가상 담당자 시연 확정 | 알파·브라보·찰리 닉네임과 예시 이메일 사용 |
| 실제 지도 공급자 | Kakao 우선 검토 (가정) | 공식 문서에 따라 서비스 이용 설정 확인 |
| JavaScript 키 | 미준비 | 실제 연동 시 사용자가 로컬에서 설정, 채팅에 키를 올릴 필요 없음 |
| 실행 주소 | 미정 | 로컬 HTTP 서버 또는 배포 도메인 등록 후 실제 모드 확인 |

## 4. 만드는 순서
| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| 1 | 검색·결과·지도·상세의 한 화면 뼈대 | 소개 섹션 없이 기능에 바로 접근 |
| 2 | 색 변수·글꼴·영문 로고 적용 | 밝은 남색과 읽기 쉬운 대비 |
| 3 | 예시 데이터와 결과 목록 | 동명 장소 2곳 이상, 구분 주소 키워드 표시 |
| 4 | 선택 상태와 주소·좌표·핀 동기화 | 장소 변경 후 모든 영역이 같은 장소 표시 |
| 5 | 담당 패널 | 해당 장소의 결정된 가상 담당자, 시연 배지 |
| 6 | 모바일 높이 배분과 패널 | 선택 후 지도·핵심 상세가 기본 화면에 보임 |
| 7 | 로딩·빈 결과·오류·키보드 처리 | 사용자가 다음 동작을 이해할 수 있음 |
| 8 | 준비된 경우 실제 검색·지도 연결 | 주소 검색·건물명 검색·좌표 주소 보완 검증 |
| 9 | 완료 기준 점검 | 데스크톱·모바일·긴 주소·접근성 확인 |

## 5. 구현 메모
### 화면 배치
- 데스크톱: 상단 검색창, 왼쪽 결과 목록, 오른쪽 지도와 상세.
- 모바일: 작은 헤더와 검색창, 가변 높이 지도, 줄바꿈되는 주소·좌표, 담당 버튼.
- 모바일 결과 목록과 담당 정보는 필요할 때 패널로 펼쳐 지도 영역 위에 표시. 닫기 버튼과 포커스 복귀를 지원합니다.
- 기준 화면에서는 한 화면 구성을 우선하고, 긴 주소·글자 확대·키보드 등장 시 내용 접근성을 위해 스크롤을 허용합니다.

### 데이터와 상태
- 공통 장소 데이터: `id`, `name`, `roadAddress`, `lotAddress`, `latitude`, `longitude`, `region`, `assigneeId`, `source`.
- 검색어·검색 상태·결과 목록·선택 ID·열린 패널을 분리해서 관리합니다.
- 이전 요청 결과를 무시할 수 있는 요청 번호를 사용합니다. 장소 변경 시 담당 패널은 닫습니다.
- 가상 주소는 실제 지도 좌표처럼 제시하지 않습니다. 예시 지도는 ‘시연용 지도’로 표시하고, 실제 장소를 예시로 쓸 때는 주소·좌표 일치를 별도로 확인합니다.
- 실제 연동은 검색 공급자를 교체할 수 있도록 검색/지도 처리 부분을 함수로 분리합니다.

### 실제 API 모드
- Kakao JavaScript SDK의 services 기능을 검토하여 주소·키워드 검색과 좌표 기반 주소 보완을 연결합니다.
- 키 발급·도메인 등록 후 HTTP(S)에서 실행합니다. API 없이 예시 모드를 확인할 수 있게 합니다.
- 비밀 REST 키를 HTML에 넣지 않습니다. 실제 지도 제공자 표시를 가리거나 제거하지 않습니다.
- 서비스 설정 또는 네트워크 오류를 빈 검색 결과와 구분합니다.
- 검색어가 지도 제공자에게 전달됨을 입력 영역 근처에 짧게 안내합니다.

공식 문서: [시작 가이드](https://apis.map.kakao.com/web/guide/), [JavaScript API 문서](https://apis.map.kakao.com/web/documentation/).

## 6. 확인 방법
| 항목 | 시나리오 | 기대 결과 |
|---|---|---|
| 검색 방식 | 도로명 / 지번 / 건물명 각각 입력 | 적합한 결과를 선택 가능 |
| 중복 이름 | 동명 건물 2곳 이상 검색 | 지역·도로명·번지로 구별 |
| 선택 변경 | 결과 A 선택 후 B 선택 | 지도 핀·주소·좌표·담당 일치 |
| 요청 경합 | 빠르게 다른 검색 수행 | 오래된 결과가 새 결과를 덮지 않음 |
| 주소 누락 | 도로명 주소 없는 결과 | ‘도로명 주소 없음’ 표시 |
| 담당자 | 같은 장소 재선택 | 같은 가상 담당자와 시연 표시 |
| 예외 | 빈 입력, 무결과, 네트워크 실패 | 각각 다른 안내와 재시도 |
| 화면 | 1280×800, 375×667, 390×844 | 가로 넘침 없음, 기본 핵심 정보 확인 |
| 예외 화면 | 긴 주소, 글자 확대, 키보드 | 글자 잘림 없이 스크롤·패널로 접근 |
| 키보드 | Tab, Enter, Escape | 검색·선택·패널 닫기와 포커스 복귀 |
| 실제 연동 | 키·도메인 준비 후 실제 장소 검색 | 지도·핀·두 주소·좌표 일치 확인 |

예시 모드의 동작 확인을 실제 API 검증으로 간주하지 않습니다. 실제 모드 미검증 항목은 완료 보고에서 구분합니다.

## 8. 구현·검증 결과
- `index.html`: 예시 검색, 결과 선택, 지도 핀, 두 주소와 좌표, 좌표 복사, 가상 담당자, 실제 지도 연결 설정 구현.
- 브라우저 검증 통과: 예시의 도로명·지번·건물명 검색, 동명 결과 구분, 담당자 연결, 빈 입력·무결과, 창 닫기·포커스 복귀.
- 1280×800, 375×667, 390×844에서 가로 넘침 없이 기본 화면이 뷰포트 안에 배치됨을 확인. 데스크톱과 모바일 스크린샷도 확인.
- 모의 SDK 검증 통과: 실제 모드 전환, 주소 보완, 추가 결과, 이전 응답 무시, 검색 오류.
- 실제 Kakao 키가 없어 실서비스 지도·검색은 미검증. 키와 도메인 준비 후 실제 장소로 별도 확인 필요.
