# 추적자 — Location Tracker PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | v0.2 · 로컬 시연 구현, 실제 API 검증 대기 |
| 작성일 | 2026-11-06 |
| 작성자 | 추적자 · 1인 팀 |
| 관련 문서 | logo-prompt.md, build-plan.md |

PRD(Product Requirements Document)는 누구를 위해 어떤 기능을 왜 만드는지 정리한 제품 기획서입니다. 이번 결과물은 팀 소개보다 **주소 검색과 위치 확인 기능이 중심인 한 화면 웹 도구**입니다.

## 1. 배경 · 문제
- 일반 사용자는 도로명, 지번, 건물명 등 서로 다른 방식으로 장소를 찾습니다.
- 같은 이름의 장소가 여러 곳이면 지역과 주소를 비교해야 합니다.
- 지도, 좌표, 두 주소 체계와 담당 정보를 한곳에서 확인하고 싶습니다.
- ‘추적’은 입력한 주소에 해당하는 고정 장소를 찾는 의미입니다. 기기의 실시간 GPS 수집은 범위에 포함하지 않습니다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 |
|---|---|
| 익숙한 표현으로 검색 | 도로명·지번·건물명 각각으로 검색하고 결과를 선택할 수 있음 |
| 동명 장소를 구별 | 선택 전 결과마다 장소명과 시·군·구, 도로명·번지 등 주소 정보가 보임 |
| 위치를 한눈에 확인 | 선택한 결과의 핀, 위도·경도, 도로명·지번 주소가 같은 장소를 가리킴 |
| 담당자 확인 | ‘담당’ 버튼을 누르면 해당 장소의 가상 담당자와 시연 표시가 보임 |
| 휴대폰에서도 사용 | 375×667, 390×844 화면에서 키보드와 펼친 패널이 없을 때 검색·지도·핵심 상세를 한 화면에 표시 (검증 크기는 가정) |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 제공할 답 | 기대 행동 |
|---|---|---|---|
| 일반 사용자 | 여기가 어디인가? 같은 이름 중 어느 곳인가? | 주소로 구분되는 검색 결과, 지도 핀, 좌표, 두 종류 주소 | 검색 → 목록에서 선택 → 위치 확인 → 필요하면 담당 버튼 |

## 4. 범위
**이번에 만드는 것**
- 도로명·지번 주소 검색 및 건물명 키워드 검색.
- 여러 결과의 목록과 주소 기반 구분 정보, 추가 결과 보기.
- 선택한 장소의 지도, 핀 1개, 위도·경도(WGS84), 도로명·지번 전체 주소.
- 장소별 가상 담당자 표시.
- 데스크톱·모바일 대응과 검색·오류·빈 결과 안내.
- API 연결 전에도 흐름을 확인할 수 있는, 명확히 표시된 예시 모드 (가정).

**이번 범위에서 제외**
- 실시간 사람·기기 위치 추적, 경로 안내, 로그인, 담당자 관리 화면, 검색 이력 서버 저장.
- 팀 소개 카드나 ‘우리가 만든 도구’의 별도 섹션. 검색 도구의 한 화면 구성에 집중합니다.

## 5. 정보 구조
| 영역 | ID | 내용 |
|---|---|---|
| 헤더 | `#header` | Location Tracker 영문 로고, 작은 팀명 ‘추적자’ |
| 검색 | `#search` | ‘도로명, 지번, 건물명을 입력하세요’ 입력창과 검색 버튼 |
| 결과 | `#results` | 결과 수, 장소명, 구분 주소, 검색어 강조, 추가 결과 |

| 상세 | `#details` | 장소명, 도로명·지번 전체 주소, 위도·경도, 담당 버튼 |
| 담당 | `#assignee` | 펼쳐지는 가상 담당 정보 |

## 6. 화면 구성
```text
데스크톱
[Location Tracker / 추적자]
[주소·건물명 입력                          검색]
[검색 결과 목록        ][지도                    ]
[장소명·구분 주소      ][선택 장소 / 도로명·지번   ]
[추가 결과            ][위도·경도          담당  ]

휴대폰
[Location Tracker]
[주소·건물명 입력        검색]
[결과 N개 · 결과 목록 열기] ← 검색 직후 목록 펼침
[지도 · 선택 위치 핀        ]
[장소명                    ]
[도로명: 전체 주소          ]
[지번: 전체 주소            ]
[위도 / 경도          담당  ]
```
- 모바일 검색 결과는 지도 영역 위 패널로 열고, 선택 후 접어 지도와 상세를 보여 줍니다.
- 담당 정보도 같은 방식의 하단 패널로 표시하고 닫으면 기본 화면으로 돌아갑니다.
- 기본 화면은 `100dvh`와 안전 영역을 고려한 높이 배분. 지도는 남는 공간을 차지합니다.
- 주소는 말줄임하지 않고 줄바꿈합니다. 긴 주소, 확대 글꼴, 작은 세로 높이, 가로 모드에서는 세로 스크롤을 허용하여 내용을 유지합니다.
- 키보드가 열린 동안에는 입력과 결과 선택을 우선하며, 모든 정보를 동시에 억지로 축소하지 않습니다.

## 7. 콘텐츠와 동작 상세
### 7-1. 검색과 결과 선택
- 검색 버튼 또는 Enter로 실행. 공백 입력이면 ‘주소나 건물명을 입력해 주세요’ 표시.
- 주소 검색과 장소 키워드 검색 결과를 모아 장소명·주소·좌표 기준으로 중복을 제거합니다 (처리 방식 가정).
- 각 결과는 장소명, 시·군·구/읍·면·동, 도로명과 건물번호 또는 지번을 표시합니다. 검색어와 일치하는 부분을 강조하되 강조만으로 구분을 대신하지 않습니다.
- 예시 결과: ‘중앙도서관 · 가상시 동구 · 솔빛로 12’와 ‘중앙도서관 · 가상시 서구 · 별빛로 48’. 이는 UI 설명용 가상 주소이며 실제 지도 결과로 사용하지 않습니다.
- 여러 결과면 자동으로 첫 항목을 확정하지 않습니다. 사용자가 직접 선택합니다. 1건일 때 자동 선택은 기본 동작으로 둡니다 (가정).
- 결과가 더 있으면 ‘더 보기’를 제공합니다. 목록은 자체 스크롤로 모든 결과에 접근할 수 있습니다.
- 늦게 도착한 이전 검색 응답이 최신 검색이나 선택 결과를 덮어쓰지 않도록 합니다.

### 7-2. 선택한 위치
- 선택 변경 시 지도 중심·핀·주소·좌표·담당 데이터를 함께 갱신합니다.
- 표시 순서는 ‘위도’, ‘경도’. 좌표 객체는 이름으로 구분하여 x=경도, y=위도 혼동을 방지합니다.
- 소수점 6자리 표시는 기본값 (가정). 표기 자릿수가 측량 정확도를 의미하지는 않습니다.
- 검색 결과에 주소가 부족하면 좌표 기반 주소 조회로 보완합니다. 도로명 주소가 없는 장소는 ‘도로명 주소 없음’, 조회 실패는 ‘주소를 불러오지 못했습니다’로 구별합니다.
- 아직 선택하지 않았으면 ‘검색 결과에서 장소를 선택해 주세요’로 안내합니다.

### 7-3. 가상 담당자
- 버튼 이름은 ‘담당’. 선택된 장소가 없으면 비활성화합니다.
- 기본 데이터는 ‘동부 지역 → 가상 담당자 알파’, ‘서부 지역 → 가상 담당자 브라보’, 나머지 → ‘가상 담당자 찰리’와 같은 지역 기준 매핑입니다 (가정).
- 장소 식별자 또는 주소를 기준으로 결정하여 같은 장소에 재방문해도 담당자가 바뀌지 않게 합니다.
- 표시 항목: 닉네임, 담당 구역, ‘시연용 가상 담당자’ 배지, 예시 연락처 `team@example.com`.
- 선택 장소 변경 시 열린 담당 패널을 닫고 새 장소의 담당으로 갱신합니다.

### 7-4. 상태 안내
| 상태 | 안내와 동작 |
|---|---|
| 최초 진입 | ‘주소를 입력하면 지도와 좌표를 확인할 수 있어요’ |
| 검색 중 | 검색 중 표시, 중복 제출 방지 |
| 결과 없음 | ‘검색 결과가 없어요. 지역명이나 번지를 함께 입력해 보세요’ |
| 검색 실패 | 입력값 유지, 재시도 버튼 |
| 지도 실패 | 주소·좌표는 유지, 지도 재시도 안내 |
| API 미설정 | 예시 모드 배지, 예시 검색 안내. 실제 조회 성공처럼 표시하지 않음 |

## 9. 반응형 · 접근성
- 가로 스크롤 없음. 데스크톱 2열, 휴대폰 1열. 소개형 페이지의 햄버거 메뉴는 사용하지 않습니다.
- 입력창에 보이는 레이블, 버튼에 명확한 이름, 키보드 포커스, 최소 44px 터치 영역 확보.
- 결과 목록은 키보드로 선택 가능. 로딩·결과 수·오류는 스크린리더 상태 메시지로 전달.
- 펼친 패널은 닫기 버튼과 Escape를 지원하고 닫을 때 실행 버튼으로 포커스 복귀.
- 지도 조작 없이도 텍스트로 위치를 확인할 수 있게 합니다. 일반 글자 대비 4.5:1 이상을 확인합니다.

## 10. 기술 조건
- 기본 산출물은 CSS·JS를 포함한 `index.html` 한 파일과 선택적 이미지입니다. 빌드 도구 없이 실행합니다.
- 실제 지도·주소 검색 공급자는 Kakao 지도 JavaScript API 및 services 라이브러리를 우선 검토합니다 (가정). addressSearch, keywordSearch, coord2Address를 조합할 계획입니다.
- 실제 API 모드는 JavaScript 키 발급, 서비스 이용 설정 확인, 실행 도메인 등록, HTTP(S) 서버가 필요합니다. 파일 더블클릭만으로 실제 지도 동작을 보장하지 않습니다.
- API 키는 사용자에게 채팅으로 요청하거나 저장소에 커밋하지 않고 로컬 설정으로 적용합니다. 브라우저용 JavaScript 키는 공개 클라이언트 식별자이므로 도메인 제한을 설정하며, REST 비밀키를 HTML에 넣지 않습니다.
- 예시 모드는 API 없이 동작하며 예시 지도/핀은 시연임을 명시합니다. 실제 검색은 연결 후 별도 검증합니다.
- 검색어는 지도 제공자에게 전달됩니다. 입력 영역에 짧게 고지하며 검색 이력을 별도로 저장하지 않습니다 (가정).

공식 참고 문서 (2026-11-06 확인):
- [Kakao 지도 시작 가이드](https://apis.map.kakao.com/web/guide/): 키·도메인 등록과 웹 서버 실행.
- [Kakao 지도 JavaScript API 문서](https://apis.map.kakao.com/web/documentation/): 지도·마커·services 검색 및 좌표 변환.

## 13. 열린 질문 · 가정
- API 공급자는 Kakao 우선 검토. 실제 키·이용 설정·도메인·호출량 조건은 연결 시 확정합니다.
- 가상 담당자 지역 매핑, 좌표 표시 자릿수, 결과 1건 자동 선택은 제작 시 조정 가능합니다.
- 기본 색과 검증할 화면 크기는 제안값입니다.
- 로고 이미지는 없습니다. 핀 SVG와 영문 글자 로고를 사용합니다. 첨부 텍스트 디자인을 참고했습니다.
