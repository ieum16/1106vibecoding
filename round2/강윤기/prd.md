# AI 표준팀 팀 소개 페이지 PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 v0.1 · 제작 전 검토 |
| 작성일 | 2026-11-06 |
| 작성자 | AI 표준팀 |
| 관련 문서 | logo-prompt.md, build-plan.md |

PRD는 무엇을, 누구를 위해, 왜 만드는지 정리하는 제품 요구사항 문서입니다.

## 1. 배경 · 문제
AI를 처음 사용하는 직원은 어디서 시작하고 어떤 스킬을 써야 하는지 판단하기 어렵습니다. AI 개발 가이드와 스킬을 설계하는 팀의 역할, 입문 자료, 요청 방법을 한 페이지에서 안내합니다. 연습용 팀 소개 페이지로 작성하며 회사 내부 정보는 포함하지 않습니다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 (검증 계획) |
|---|---|
| 팀 역할 이해 | 처음 보는 사람이 1분 안에 팀의 역할을 설명 |
| 가이드 탐색 | 시작 버튼에서 입문 가이드까지 두 번 이내 클릭 |
| 스킬 선택 | 문서·회의록·요약 분류와 사용 예시로 적합한 스킬 선택 |
| 요청 작성 | 필수 항목을 작성하고 요청문을 복사 가능 |
실제 사용자 검증은 아직 진행하지 않았습니다.

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줄 답 | 기대 행동 |
|---|---|---|---|
| AI를 처음 사용하는 직원 | 어떻게 시작하고 어떤 도구를 쓰나요? | 쉬운 단계별 가이드와 예시 | 가이드 확인, 스킬 탐색·사용, 새 가이드·스킬 제작 요청 |

## 4. 범위
이번 범위: 팀 소개, 시작 가이드, 스킬 모음, 제작 요청 양식, FAQ, 반응형 단일 페이지.
요청 양식은 요청문 생성·복사까지만 구현합니다(가정). 실제 접수로 오해하지 않도록 안내합니다.
제외: 로그인, 서버 접수, 실제 사내 시스템 연결, 스킬 자동 설치, 사용 통계 수집.

## 5. 정보 구조 (메뉴)
| 메뉴 | 섹션 ID | 내용 |
|---|---|---|
| 팀 소개 | #intro | 역할·비전·주요 업무 |
| 시작 가이드 | #guides | 입문·프롬프트·안전·검토 |
| 스킬 모음 | #skills | 분류·검색·사용 예시·준비 상태 |
| 제작 요청 | #request | 요청문 작성·복사·처리 절차 |
| 자주 묻는 질문 | #faq | 설치·사용·오류·문의 |

## 6. 화면 구성 (위에서 아래로)
고정 헤더 → 한 줄 소개와 시작 버튼 → 팀 주요 업무 → 단계별 시작 가이드 → 추천 스킬·스킬 모음 → 제작 요청 → FAQ → 푸터.
첫 화면에 ‘처음이라면 여기부터’와 ‘스킬 둘러보기’ 버튼을 배치합니다.

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 제목: AI의 첫걸음부터, 팀의 새로운 기준까지.
- 보조 문구: AI 개발 가이드와 실무 스킬로 누구나 자신 있게 시작하도록 돕습니다.
- 버튼: 처음이라면 여기부터 / 스킬 둘러보기
### 7-2. 업무 카드
| 제목 | 설명 | 요청 예시 |
|---|---|---|
| 개발 가이드 설계 | AI 활용 단계와 기준을 쉽게 정리 | 처음 사용할 도구의 안내가 필요해요 |
| 실무 스킬 설계 | 반복 작업을 재사용 가능한 절차로 구성 | 회의록을 일정한 형식으로 정리하고 싶어요 |
| 사용 기준 정리 | 안전한 입력과 결과 검토 방법 안내 | AI 결과를 어떻게 검토하나요? |
가이드: AI 도구 시작하기, 프롬프트 작성법, 안전한 정보 입력, 결과 검토 방법.
각 가이드는 짧은 단계와 가상 예시를 제공합니다. 특정 회사 정책으로 표현하지 않습니다.
스킬: 문서 작성, 회의록 정리, 자료 요약. 실제 스킬 파일이 없으므로 ‘준비 중’ 배지와 사용 예시를 제공합니다. 사용 가능하거나 설치 완료된 것처럼 표시하지 않습니다.
요청 항목: 유형(가이드/스킬), 제목, 현재 불편한 점, 원하는 결과, 입력·출력의 가상 예시. 개인정보를 요구하지 않습니다.
처리 절차: 요청 정리 → 검토 → 설계·검증 → 공유. 응답 기한은 미정입니다.
FAQ: 스킬이란 무엇인가요, 설치는 어떻게 하나요, 원하는 결과가 안 나오면 어떻게 하나요, 어떤 정보를 입력하면 안 되나요, 새 스킬은 어떻게 요청하나요.
### 7-3. 문의

|---|---|
| 요청 채널 | #채널명 (예시) |

| 응답 시간 | 미정 · 실제 운영 기준 확인 필요 |

## 8. 디자인 가이드
| 항목 | 값 |
|---|---|
| 메인 색 | 미드나이트 네이비 #0B1020 (제안) |
| 보조 색 | 차가운 백색 #F5F7FC, 카드 #141D32 (제안) |
| 포인트 색 | 청록 #5EEAD4, 보라 #A78BFA (제안) |
| 느낌 | 미래지향적 / 세련된 / 명료한 |
| 글꼴 | Pretendard, 시스템 글꼴 대체 |
| 모서리·그림자 | 16~24px 모서리, 얇은 경계선, 제한된 빛 효과 |
| 로고 | images/logo.png · 독자적인 추상 기하학 심벌 |
| 참고 이미지 | 없음 · 사용자 언급 브랜드는 단순성·상징성 참고 |
짙은 첫 화면과 밝은 콘텐츠 영역을 조합해 초보자가 읽기 쉽게 구성합니다(제안). 과도한 네온·입자 애니메이션은 쓰지 않습니다. Claude의 방사형 심벌이나 ChatGPT의 매듭 형태를 그대로 재현하지 않습니다.

## 9. 반응형 · 접근성
375px~1280px 이상에서 가로 스크롤 없이 표시. 카드 3열 → 2열 → 1열. 640px 아래 햄버거 메뉴. 키보드 조작, 포커스 표시, 충분한 명도 대비, 이미지 대체 텍스트, 움직임 줄이기 설정을 지원합니다.

## 10. 기술 조건
index.html 안에 CSS·JS를 포함합니다. 빌드 도구 없이 열 수 있고 외부 의존은 글꼴 CDN 정도로 제한합니다. 검색·분류·FAQ·요청문 생성은 브라우저에서 동작합니다. 파일 환경에서 클립보드가 제한되면 텍스트 선택·수동 복사를 제공합니다.
