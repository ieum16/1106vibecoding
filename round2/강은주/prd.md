# 크리에이티브 스튜디오 팀 소개 페이지 PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 v0.1 |
| 작성일 | 2026-11-06 |
| 작성자 | 크리에이티브 스튜디오 |
| 관련 문서 | logo-prompt.md, build-plan.md |

PRD는 무엇을, 누구를 위해, 왜 만드는지 정리하는 제품 기획서입니다.

## 1. 배경 · 문제
소상공인은 예약, 고객 문의, 견적 작성에 시간을 쓰지만 어떤 업무를 자동화할 수 있는지 판단하기 어렵다. 2명으로 구성된 크리에이티브 스튜디오는 반복 업무를 자동화 도구로 바꾸는 팀이다. 제공 서비스를 쉽게 설명하고 제작 문의로 연결하는 소개 페이지가 필요하다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 (측정 방법) |
|---|---|
| 제공 서비스 이해 | 페이지 검토자가 예약 관리·고객 문의 정리·견적서 작성을 찾을 수 있다 |
| 문의 진입 경로 제공 | 메인 및 서비스 영역의 문의 버튼이 문의 섹션으로 이동한다 |
| 실제 문의 준비 | 예시 연락처를 실제 운영 채널로 교체한 후 문의 링크를 검증한다 |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줘야 할 답 | 기대 행동 |
|---|---|---|---|
| 자동화가 필요한 소상공인 | 내 업무도 자동화할 수 있는지, 얼마나 걸리는지 | 서비스별 예시와 범위에 따른 일정 안내 | 자동화 제작 문의 |

## 4. 범위
이번에 만드는 것: 팀 소개, 서비스 카드 3개, 준비 중 도구 카드, FAQ, 문의 안내를 담은 한 장짜리 반응형 페이지.

이번에 안 만드는 것: 자동화 도구 자체, 로그인, 서버, 결제, 문의 전송 시스템, 실제 서비스 연동.

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 제목: 반복 업무는 줄이고, 사장님의 시간은 더 가치 있게.
- 보조 문구: 크리에이티브 스튜디오는 반복 업무를 자동화 도구로 바꾸는 2명 팀입니다. 예약 관리부터 고객 문의 정리, 견적서 작성까지 필요한 흐름을 함께 설계합니다.
- 버튼: 자동화 제작 문의 → #contact
- 보조 링크: 어떤 업무가 가능한가요? → #work
- 위 문구는 사용자 답변을 바탕으로 작성한 카피 초안이다.

### 7-2. 업무 카드
| # | 제목 | 설명 | 요청 예시 |
|---|---|---|---|
| 1 | 예약 관리 | 반복되는 예약 확인과 일정 정리 흐름을 설계합니다. | 매일 들어오는 예약을 한눈에 정리하고 싶어요. |
| 2 | 고객 문의 정리 | 문의 내용과 처리 상태를 모아 관리하는 흐름을 설계합니다. | 자주 오는 문의를 분류하고 답변 준비 시간을 줄이고 싶어요. |
| 3 | 견적서 작성 | 반복 입력하는 항목을 정리하고 견적서 초안 작성 흐름을 설계합니다. | 품목과 수량으로 견적서 초안을 만들고 싶어요. |

위 예시는 상담 가능한 업무를 설명하며 이미 구현된 기능이나 특정 외부 서비스 연동을 보장하지 않는다.

### 7-3. 만든 도구
- 점선 테두리 카드에 ‘준비 중’ 배지 표시.
- 문구: 소상공인의 일상을 가볍게 할 도구를 준비하고 있어요.
- 실제 고객 사례, 성과 수치, 이용 후기를 만들지 않는다.

### 7-4. FAQ
- 어떤 업무를 자동화할 수 있나요?
  - 예약 확인과 일정 정리, 고객 문의 분류, 견적서 초안 작성처럼 반복되는 규칙이 있는 업무부터 살펴봅니다. 현재 사용하는 도구와 업무 흐름을 알려 주시면 가능한 범위를 함께 정합니다.
- 제작 기간은 얼마나 걸리나요?
  - 업무의 복잡도와 연결할 서비스에 따라 달라집니다. 상담에서 필요한 기능과 자료를 확인한 뒤 제작 범위와 예상 일정을 안내합니다.

### 7-5. 문의
| 항목 | 값 |
|---|---|
| 이메일 | team@example.com (예시, 운영 전 교체 필요) |
| 문의 준비 정보 | 업종, 반복 업무, 현재 방식, 원하는 결과 |
| 응답 시간 | 운영 전 확정 필요; 응답 시간 약속을 표시하지 않음 |

예시 연락처임을 화면에 명시한다. 실제 전송을 하는 폼이나 전송 완료 메시지는 만들지 않는다. 문의 예시 문구를 복사하는 버튼을 제공한다 (가정). 이메일은 실제 주소 확정 전까지 일반 텍스트로 표시한다 (가정).

## 9. 반응형 · 접근성
- 375px~1280px 이상에서 가로 스크롤 없이 표시.
- 서비스 카드: 데스크톱 3열, 태블릿 2열, 휴대폰 1열.
- 640px 아래 햄버거 메뉴. 키보드 조작, 포커스 표시, 메뉴 상태 안내 지원.
- 충분한 글자 대비, 의미 있는 대체 텍스트, 제목 순서 유지.
- 고정 헤더에 섹션 제목이 가려지지 않게 이동 여백 적용.

## 10. 기술 조건
- index.html 하나에 CSS·JS 포함. 빌드 도구 없이 더블클릭으로 열림.
- 서버와 외부 데이터 전송 없음. 글꼴 CDN 실패 시 기본 글꼴 사용.
- images/logo.png가 있으면 표시하고, 없거나 로드 실패 시 임시 글자 로고 표시.
- 문의 문구 복사는 로컬 파일 환경의 권한 제한에 대비해 직접 선택·복사 안내 제공.

## 13. 열린 질문
- 운영용 연락처와 응답 시간은 공개 전에 정한다.
- 보라색의 구체 색상, 세 번째 분위기 단어, 문구 복사 기능은 초안의 가정이며 수정 가능하다.
- 팀 로고는 추후 추가할 수 있다.

## 14. 첨부 디자인 가이드 반영
사용자가 제공한 Claude.com 디자인 분석 문서를 참고했다. 따뜻한 크림 배경, 명조 제목과 고딕 본문, 96px 안팎의 섹션 여백, 크림·어두운 면의 대비를 적용한다. 강조색은 팀 색상인 차분한 보라로 변경한다. 타사 로고·브랜드명·전용 폰트를 사용하지 않는다. 개발자 코드 화면 대신 예약·문의·견적을 연결하는 업무 흐름 구성 예시를 보여 준다. 문의 채널이 아직 정해지지 않아 준비 중이라고 명시한다.
