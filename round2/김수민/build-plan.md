# DX Service팀 홈페이지 제작 계획서

## 1. 만들 것
- prd.md를 기준으로 한 장짜리 팀 소개 페이지 index.html을 만든다.
- 목적: 누구나 웹서비스를 개발·운영하는 6명 팀의 역할을 이해한다.
- 제작은 사용자가 이 계획을 검토하고 진행 의사를 밝힌 후 시작한다.

## 2. 파일 구조
```text
team-page/
├─ prd.md
├─ logo-prompt.md
├─ build-plan.md
├─ index.html          ← 확인 후 제작
└─ images/             ← 이미지 사용 시 추가
   ├─ logo.png         ← 선택, 없으면 DX 글자 로고
   └─ reference.png    ← 선택
```

## 3. 준비물 체크
| 준비물 | 상태 | 대응 |
|---|---|---|
| 로고 이미지 | 없음 · 사용자 위임 | DX 글자 로고 사용, 추후 이미지로 교체 가능 |
| 참고 이미지 | 없음 · 사용자 위임 | 파랑·전문적·여백 많은 PRD 가이드 적용 |
| 업무 내용 | 확정 | 기획, 프론트엔드, 백엔드, 운영, 장애 대응, 개선 |
| 서비스 목록 | 미제공 | 준비 중 카드 표시 |
| 문의 정보 | 예시 | team@example.com, #채널명, 미연결 표시 |

## 4. 만드는 순서
| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| 1 | 헤더·섹션 4개·푸터 작성 | 의미 있는 문서 구조와 메뉴 연결 |
| 2 | 색·글꼴·여백 변수 적용 | 흰 배경과 파란 강조, 충분한 여백 |
| 3 | 한 줄 소개와 6명 팀 표시 | 역할이 바로 읽히는지 |
| 4 | 업무 카드 6개 작성 | 쉬운 설명과 업무 범위 일치 |
| 5 | 서비스 준비 중 카드 작성 | 점선 테두리·배지 표시 |
| 6 | 예시 문의 안내 작성 | 실제 전송 기능으로 오해하지 않는지 |
| 7 | DX 로고 및 이미지 대체 처리 | 이미지가 없을 때도 정상 표시 |
| 8 | 반응형과 메뉴 구현 | 375px와 데스크톱, 키보드 조작 |
| 9 | 최종 확인과 수정 | PRD 완료 기준 충족 |

## 5. 섹션별 구현 메모
| 섹션 | 레이아웃 | 데스크톱 → 휴대폰 |
|---|---|---|
| 헤더 | 로고 왼쪽, 메뉴 오른쪽, 상단 고정 | 640px 미만에서 햄버거 메뉴 |
| 소개 | 큰 제목, 보조 문구, 업무 보기 버튼, 절제된 그래픽 | 2열 → 1열 |
| 업무 | 아이콘·제목·쉬운 설명·협업 예시 | 3열 → 2열 → 1열 |
| 서비스 | 넉넉한 폭의 준비 중 카드 | 전체 폭 유지 |
| 문의 | 짙은 파란 영역에 예시 안내 | 1열로 정리 |

## 6. 확인 방법
- 브라우저 미리보기가 가능하면 데스크톱과 375px 폭에서 확인한다.
- 메뉴 4개 이동, 고정 헤더의 제목 가림, 모바일 메뉴 열기·닫기를 확인한다.
- 가로 스크롤, 글자 대비, 키보드 포커스, 로고 대체 표시를 확인한다.
- 문의 정보가 예시로 보이고 준비 중 서비스에 허구의 실적이 없는지 확인한다.
- 미리보기가 불가능하면 실행 여부를 명확히 밝히고 index.html 더블클릭으로 확인하는 방법을 안내한다.
- 최종적으로 prd.md의 완료 기준을 대조한다.

## 7. 만든 뒤 고치기 예시
- “서비스 준비 중 카드를 실제 서비스 소개로 바꿔 줘.”
- “파란색을 조금 더 밝게 해 줘.”
- “멤버 소개 칸을 문의 위에 추가해 줘.”

## 8. 디자인 수정 기록 (2026-11-06)
- 사용자 제공 Apple 디자인 분석을 반영했다. 밝고 어두운 전체 폭 섹션, 중앙 제목, 두 줄 내비게이션, 알약형 버튼으로 수정했다.
- 장식용 그라데이션과 카드 그림자를 제거하고, 웹서비스 업무 흐름을 나타내는 예시 화면을 HTML/CSS로 구성했다.
- 모바일 메뉴 분기점을 834px 미만으로 조정했다. 업무 내용과 문의 예시는 유지했다.
