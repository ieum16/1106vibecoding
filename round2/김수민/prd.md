# DX Service팀 소개 페이지 PRD

| 항목 | 내용 |

> PRD는 무엇을, 누구를 위해, 왜 만드는지 정리한 제품 요구사항 문서입니다.

## 1. 배경 · 문제
- DX Service팀은 웹서비스를 개발하고 운영하는 6명 팀이다.
- 누구나 팀의 역할과 업무 범위를 쉽게 이해하도록 소개 페이지가 필요하다.
- 개발 용어를 모르는 방문자도 읽을 수 있도록 전문 용어에 쉬운 설명을 붙인다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 (측정 방법) |
|---|---|
| 처음 방문한 사람이 팀의 역할을 이해한다 | 비개발자를 포함한 3명에게 페이지를 보여 주고 팀의 역할과 업무 2가지를 설명할 수 있는지 확인 (가정) |
| 업무의 전체 흐름을 이해한다 | 기획 → 프론트엔드·백엔드 개발 → 운영·장애 대응·개선의 관계를 파악할 수 있는지 확인 (가정) |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줘야 할 답 | 기대 행동 |
|---|---|---|---|
| 모든 방문자 | 어떤 팀인가? | 웹서비스를 기획·개발·운영하는 6명 팀 | 팀 역할 이해 |
| 비개발자 | 개발·운영 업무가 무엇인가? | 업무 6종의 쉬운 설명 | 업무 범위 이해 |
| 협업에 관심 있는 방문자 | 어떤 일을 함께할 수 있나? | 업무 카드와 문의 안내 | 협업 가능 영역 이해 |

## 4. 범위
**이번에 만드는 것**
- 소개 · 하는 일 · 우리가 만든 서비스 · 문의 섹션의 한 장짜리 페이지
- 주요 업무 6개 카드, 팀원 수 6명 표시
- 파란색의 깔끔하고 전문적이며 여백 많은 디자인
- 휴대폰 메뉴, 임시 글자 로고, 서비스 준비 중 카드

**이번 범위 밖**
- 로그인, 게시판, 관리자 기능, 서버로 전송하는 문의 폼
- 실제 서비스 실적·이름이나 팀원 개인정보를 추정해 작성하는 일

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 제목: 웹서비스의 시작부터, 안정적인 운영까지.
- 보조 문구: DX Service팀은 6명의 구성원이 함께 웹서비스를 기획하고 개발하며, 안정적인 운영과 지속적인 개선을 이어갑니다.
- 버튼: 우리가 하는 일 보기 → #work
- 위 문구는 사용자 답변을 바탕으로 다듬은 제안 문안이다.

### 7-2. 업무 카드
| # | 제목 | 설명 | 협업 예시 (가정) |
|---|---|---|---|
| 1 | 웹서비스 기획 | 사용자에게 필요한 기능을 찾고, 서비스의 방향과 화면 흐름을 설계합니다. | 새 서비스의 기능과 이용 흐름 정리 |
| 2 | 프론트엔드 개발 | 사용자가 직접 보고 사용하는 웹 화면을 만듭니다. | 휴대폰에서도 편하게 쓰는 화면 개발 |
| 3 | 백엔드 개발 | 화면 뒤에서 데이터와 서비스 기능이 작동하도록 시스템을 만듭니다. | 데이터 처리와 서비스 기능 구현 |
| 4 | 서비스 운영 | 서비스 상태를 살피고 안정적으로 사용할 수 있도록 관리합니다. | 서비스 상태 점검과 운영 관리 |
| 5 | 장애 대응 | 서비스에 문제가 생겼을 때 원인을 찾고 정상화하며 재발을 줄입니다. | 오류 원인 분석과 복구 |
| 6 | 서비스 개선 | 사용자 의견과 운영 결과를 바탕으로 기능과 사용성을 다듬습니다. | 불편한 이용 과정과 성능 개선 |

### 7-3. 우리가 만든 서비스
- 카드 제목: 새로운 서비스를 준비하고 있습니다.
- 설명: 소개할 서비스는 준비가 끝나면 이곳에서 만나보실 수 있습니다.
- 점선 테두리와 “준비 중” 배지, 동작하지 않는 버튼은 두지 않는다.

### 7-4. 문의
| 항목 | 값 |
|---|---|
| 요청 채널 | #채널명 (예시) |
| 이메일 | team@example.com (예시) |
| 응답 시간 | 미정 · 실제 안내는 추후 업데이트 |
| 동작 | 예시 정보임을 표시하고 전송·메일 링크는 연결하지 않음 (가정) |

## 8. 디자인 가이드
+- 기준: 사용자가 제공한 Apple 웹 디자인 분석 문서. 제품 사진 중심의 구성을 팀 소개에 맞는 코드 기반 웹서비스 예시 화면으로 해석한다.
+- 표면: 밝은 회색 #f5f5f7 소개 → 짙은 회색 #272729 업무 → 흰색 서비스 → #252527 문의 → 밝은 회색 푸터.
+- 전체 폭 섹션은 모서리·장식용 그라데이션·그림자 없이 이어진다.
+- 인터랙션 색: 밝은 표면 #0066cc, 어두운 표면의 링크 #2997ff, 포커스 #0071e3.
+- 제목: 시스템 글꼴 + Pretendard 대체, 굵기 600, 중앙 정렬. 첫 제목 56px, 작은 휴대폰 28px.
+- 본문: 17px, 굵기 400, 충분한 줄 간격. 주요 소개 문장은 21px.
+- 내비게이션: 검정 44px 상단 바 + 반투명 56px 하단 메뉴, 작은 화면 높이 조정.
+- 버튼: 파란 알약형과 외곽선 알약형, 최소 44px 높이, 누를 때 0.95 배율.
+- 업무 카드: 짙은 회색의 평평한 18px 모서리 카드, 그림자 없음, 데스크톱 3열.
+- 로고: 단색 dx 글자형. images/logo.png가 생기면 교체한다.
+- 상단 예시 화면은 실제 서비스 화면이 아님을 캡션에 표시한다.
+- 서비스 준비 중 정보와 문의 예시는 유지한다.

## 9. 반응형 · 접근성
- 375px ~ 1280px 이상에서 가로 스크롤 없이 사용한다.
- 업무 카드: 데스크톱 3열 → 태블릿 2열 → 휴대폰 1열.
- 834px 미만에서는 햄버거 메뉴, 휴대폰 좌우 여백 16px.
- 메뉴는 키보드로 조작하고 펼침 상태를 안내하며, 포커스를 눈에 띄게 표시한다.
- 고정 헤더가 이동한 섹션 제목을 가리지 않도록 한다.
- 글자 대비를 확보하고 의미 있는 이미지에 대체 텍스트를 제공한다.
- 움직임 줄이기 설정에서는 부드러운 스크롤을 줄인다.

## 10. 기술 조건
- index.html 하나에 CSS·JS를 포함하고, 빌드 도구·서버 없이 더블클릭으로 연다.
- 외부 의존성은 글꼴 CDN 정도로 제한한다.
- 로고가 없으면 인라인 SVG 글자 로고를 표시한다.
- 분석 스크립트, 개인정보 수집, 외부 데이터 전송 기능은 포함하지 않는다.
