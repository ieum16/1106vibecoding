# 경영지원팀 소개 페이지 PRD

## 한 줄 소개

인사·총무·법무·내부회계를 담당하는 가상의 6명 팀을 소개하고, 전 직원과 신규 입사자가 업무별 담당 창구와 요청 방법을 찾도록 돕는 수업용 홈페이지입니다. ‘경영지원팀’은 연습용 가상 이름이며 실제 회사나 부서를 나타내지 않습니다.

배포 주소: https://homepage-iota-pied.vercel.app/

제출 로고: images/logo.svg — 홈페이지의 주황색 ‘경’ 임시 로고를 별도 SVG로 정리했습니다. 배포본은 동일한 글자 로고를 HTML 안에서 표시합니다.

|---|---|
| 문서 상태 | v0.2 · 참고 디자인 반영 및 로컬 구현 완료, 화면 검토 대기 |

| 작성자 | 경영지원팀 · 수업용 기획 |

PRD는 무엇을, 누구를 위해, 왜 만드는지 정리한 제품 요구사항 문서입니다.

## 1. 배경 · 문제
전 직원과 신규 입사자가 인사·총무·법무·내부회계 중 어디로 어떤 요청을 해야 하는지 쉽게 파악할 수 있는 안내 페이지가 필요하다. 업무 설명과 담당 창구를 한곳에 모아 문의 경로를 찾는 수고를 줄인다. 현재 문의가 여러 경로로 흩어져 있다는 점은 (가정)이다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 · 검토 방식 |
|---|---|
| 팀 역할 이해 | 첫 화면에서 6명 팀과 4개 담당 업무를 확인할 수 있다 |
| 업무별 담당 창구 찾기 | 대표 요청 4건을 골라 각각 알맞은 업무와 창구를 찾을 수 있다 |
| 요청 준비 방법 이해 | 요청 방법에서 필요한 정보를 확인할 수 있다 |
| 신규 입사자의 정보 탐색 지원 | 메뉴에서 신규 입사자 안내와 서식 모음으로 바로 이동한다 |

성공 기준의 검토 방식은 (가정)이며, 실제 이용자 검토는 제작 후 진행한다.

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줄 답 | 기대 행동 |
|---|---|---|---|
| 전 직원 | 이 업무는 어디에 요청하나? | 업무별 대표 요청과 담당 창구 | 맞는 창구를 확인하고 요청 준비 |
| 신규 입사자 | 경영지원팀이 무엇을 도와주나? | 팀 역할, 업무 안내, 입사자 안내 | 필요한 업무와 자료 위치 파악 |

## 4. 범위
이번 버전에는 팀 소개, 업무 및 담당자, 요청 방법, 자주 묻는 질문, 서식 모음, 신규 입사자 안내를 만든다. 개인별 이름이나 연락처 없이 업무별 담당 창구를 표시한다. 자료 미제공 항목은 준비 중으로 표시한다.

로그인, 실제 요청 접수·전송, 게시판, 서버, 실제 서식 다운로드, 사내 시스템 연동은 이번 제작 범위에서 제외한다. 수업용 예시 페이지로 만들고 회사명·실제 연락처·내부 자료는 넣지 않는다.

## 6. 화면 구성
헤더(로고·6개 메뉴) → 팀 소개(담당 업무와 6명 표시) → 업무 및 담당자(4개 카드) → 요청 방법 → 자주 묻는 질문 → 서식 모음 → 신규 입사자 안내 → 푸터.

첫 화면에는 ‘업무별 창구 찾기’와 ‘신규 입사자 안내’ 이동 버튼을 둔다 (가정). 요청 창구는 업무 카드에 함께 넣어 이동 단계를 줄인다.

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 제목: 일하는 하루를 함께 돕는 경영지원팀
- 보조 문구: 인사·총무·법무·내부회계 업무를 담당하는 6명의 팀입니다. 필요한 지원과 업무별 담당 창구를 찾아보세요.
- 버튼: 업무별 창구 찾기 / 신규 입사자 안내
- 제목과 버튼 문구는 (가정)이다.

### 7-2. 업무 카드
| 업무 | 설명·대표 요청 | 창구 표시 |
|---|---|---|
| 인사 | 휴가·근태, 입퇴사 절차, 증명서 발급 | 인사 담당 창구 |
| 총무 | 비품 신청, 시설 이용, 사무환경 문의 | 총무 담당 창구 |
| 법무 | 계약서 검토, 법률 자문 요청 | 법무 담당 창구 |
| 내부회계 | 내부통제 절차, 증빙 준비, 점검 대응 | 내부회계 담당 창구 |

각 카드의 ‘요청 방법 보기’는 #request로 이동한다. 창구에는 실제 연락처 대신 ‘연락 경로 준비 중’ 표시를 둔다 (가정). 동작하지 않는 연락 버튼은 만들지 않는다.

### 7-3. 요청 방법 · 문의
업무 선택 → 요청 목적·내용·희망 일정 정리 → 해당 업무 창구 확인의 3단계를 안내한다 (가정). 실제 제출 양식이나 처리 기한은 확정하지 않는다.

| 항목 | 표시 |
|---|---|
| 업무별 연락 경로 | 준비 중 · 수업용 예시 |
| 대표 이메일 | team@example.com · 예시 주소, 실제 접수용 아님 |
| 응답 시간 | 업무별 확인 필요 · 확정 시간 미표시 |

### 7-4. FAQ · 자료 · 신규 입사자
FAQ 초안 (가정): ‘어느 업무에 요청해야 하나요?’에는 위 4개 업무 예시를 안내한다. ‘요청할 때 무엇을 준비하나요?’에는 요청 목적·내용·희망 일정을 안내한다. ‘서식은 어디에서 받나요?’에는 서식 모음이 준비 중임을 명시한다. 실제 휴가 규정이나 법률·회계 판단은 작성하지 않는다.

서식 모음은 인사·총무·법무·내부회계의 4개 준비 중 카드로 구성한다 (가정). 실제 파일이 없어 다운로드 버튼을 제공하지 않는다. 신규 입사자 안내에는 인사 절차는 인사, 비품·시설 문의는 총무로 연결하며 상세 안내 자료는 준비 중으로 둔다 (가정).

### 사용자 제공 디자인 문서 적용
2026-11-06 제공된 Apple 웹 디자인 분석 문서를 참고했다. 넓은 여백, 중앙 정렬 큰 제목, 17px 본문, 단일 강조색, 반투명 고정 메뉴, 밝고 어두운 배경 전환을 적용했다. 업무 안내 목적에 맞춰 주황색을 유지하고 제품 사진 대신 네 업무를 표현하는 인라인 SVG 도형을 배치했다. 요청 방법 구간에만 어두운 배경을 사용했다. 실제 홈페이지의 첫 제목은 ‘일하는 하루를, 조금 더 편하게.’로 다듬었다.

## 9. 반응형 · 접근성
- 데스크톱 1280px과 휴대폰 375px에서 가로 스크롤이 없어야 한다.
- 업무 카드: 데스크톱 4열 → 태블릿 2열 → 휴대폰 1열. 휴대폰 좌우 여백 16px.
- 640px 미만에서 햄버거 메뉴를 제공한다. 고정 헤더가 이동한 섹션 제목을 가리지 않게 한다.
- 키보드로 메뉴·버튼·FAQ를 조작할 수 있게 하고 포커스를 표시한다.
- 본문·버튼의 글자 대비를 확인하고 색상 외에도 글자로 상태를 표시한다. 로고에 대체 텍스트를 넣는다.

## 10. 기술 조건
index.html 한 파일에 CSS·JS를 포함한다. 서버와 빌드 도구 없이 더블클릭으로 열린다. 외부 의존 없이 구현한다 (가정). 로고 파일이 추가되면 로드하고, 로드 실패 시 임시 로고를 보여준다. FAQ는 브라우저 기본 펼침 요소를 사용한다 (가정).

## 13. 열린 질문
- 사용자 요청에 따라 참고 문서를 반영해 홈페이지를 제작했다. 로고 파일은 없어 임시 ‘경’ 로고를 사용했다.
- 실제 서식·입사자 자료와 연락 경로가 제공되면 준비 중 표시를 교체한다.
- 요청 준비 항목은 일반적인 안내 초안이며 실제 업무 절차 확정 시 수정이 필요하다.
