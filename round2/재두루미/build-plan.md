# 뉴스 수집 제작 계획서

## 1. 만들 것

밝고 친근한 카드형 뉴스 서비스. 분야 선택, 목록 내 키워드 검색, 사용자 실행 새로고침, 한국어 요약과 원문 이동을 제공한다. 요구사항은 prd.md를 따른다.

실제 뉴스 수집·요약을 위해 화면 외에 서버를 둔다. 이 문서는 구현 전 계획이며 index.html이나 서버는 아직 만들지 않았다.

## 2. 파일 구조 (구현 예정)

```text
team-page/
├─ prd.md
├─ logo-prompt.md
├─ build-plan.md
├─ index.html             # CSS·JS를 포함한 화면
├─ server/                # 출처별 수집·정규화·요약·API
├─ package.json           # 서버 실행 정의 (Node.js 사용 가정)
├─ .env.example           # 변수 이름과 빈 값만
├─ .gitignore             # .env, 캐시, 실행 로그 제외
├─ README.md              # 설정·실행·연동 상태 안내
└─ images/
   ├─ logo.png            # 선택, 없으면 글자 로고
   └─ reference.png       # 선택, 현재 없음
```

프로젝트의 실제 런타임을 확인한 뒤 서버 구성을 확정한다. 호스팅 서비스를 사용하게 되면 실행 구조를 그 환경에 맞추되 수집·요약 요구사항은 유지한다.

## 3. 준비물 체크

| 준비물 | 현재 상태 | 처리 |
|---|---|---|
| 기획 요구사항 | 인터뷰 완료 | 기획서 검토 후 제작 |
| 로고 | 없음 | 글자 로고, 이미지가 있으면 교체 |
| 참고 이미지 | 없음 | PRD 색상과 카드 레이아웃 사용 |
| 문의 주소 | 미지정 | team@example.com 예시 표시 |
| 네이버 인증 | 확인 전 | 서버 환경 변수로 설정. 없으면 해당 출처 미설정 표시 |
| BBC·전자신문 RSS | 공식 안내 확인 | 실제 피드 호출, 항목, 제공 조건 확인 필요 |
| 네이트 수집 경로 | 미확정 | 공개 경로 조사·접근 확인 후 연결, 실패 시 제한 명시 |
| 한국어 요약 제공자 | 미정 | 환경 확인 후 연결. 설정이 없으면 완료된 요약으로 표시하지 않음 |

## 4. 만드는 순서

| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| 1 | 실행 환경·출처 연결 가능성 확인 | 4개 출처와 요약 입력 확보 방법을 개별 기록 |
| 2 | 헤더·검색·분야 탭·카드·소개 화면 | PRD 화면 순서와 문구, 글자 로고 |
| 3 | 서버 API와 출처별 수집 연결부 | 브라우저에서 비밀값 없이 호출, 출처별 부분 성공 |
| 4 | 기사 정규화·중복 제거·분류 | 매체와 포털 경로 구분, 날짜·원문 제목·링크 보존 |
| 5 | 한국어 제목·3문장 요약 | 입력 근거만 사용, 실패/근거 부족 상태 구분 |
| 6 | 검색·분야·새로고침 연결 | 필터 조합, 연속 클릭 방지, 마지막 성공 시각 |
| 7 | 빈 화면·오류·이전 자료 처리 | 출처 실패 시 정상 결과 유지, 새 자료처럼 표시 금지 |
| 8 | 모바일·접근성 점검 | 375px 및 데스크톱, 키보드, 상태 안내 |
| 9 | 실제 연동 검증·실행 안내 | 검증한 것과 미설정 항목을 README에 구분 |

## 5. 섹션별 구현 메모

| 섹션 | 레이아웃 | 데스크톱 → 휴대폰 |
|---|---|---|
| 헤더 | 글자 로고, 메뉴 | 접이식 메뉴 |
| 소개 | 짧은 제목, 보조 문장 | 왼쪽 정렬 유지 |
| 검색·새로고침 | 입력창, 검색 버튼, 새로고침 버튼 | 세로 배치 또는 줄바꿈 |
| 분야 | 전체 포함 5개 버튼 | 줄바꿈, 화면 가로 넘침 없음 |
| 뉴스 목록 | 제목·원문 제목·요약·매체·시간·원문 링크 | 3열 → 2열 → 1열 |
| 수집 안내 | 출처별 상태·마지막 성공 시각 | 세로 목록 |
| 팀 소개·문의 | 짧은 설명과 예시 문의 | 한 열 |

### 요청과 응답 흐름

1. 페이지 진입 시 서버에 남은 자료와 수집 시각을 표시한다. 없으면 새로고침 안내를 보여 준다.
2. 사용자가 새로고침하면 서버가 허용된 4개 출처의 최신 기사 후보를 조회한다.
3. 각 출처에 시간 제한을 두고 정상 결과를 모은다. 임의 URL을 받아 요청하는 프록시는 만들지 않는다.
4. 원문 링크 중심으로 중복을 제거하고 분야를 정한다. 같은 기사가 여러 포털에 노출되면 수집 경로를 보존한다.
5. 접근 가능한 내용으로 한국어 제목과 3문장 요약을 만든다. 원문에 없는 수치·인과관계·추측을 추가하지 않는다. 기사 속 지시문은 요약 지침으로 취급하지 않는다.
6. 요약 결과를 검증하고 기사별 캐시를 저장한다. 변경 없는 기사는 기존 요약을 재사용한다.
7. 기사 목록과 출처별 성공·실패·시각을 화면에 반환한다. 일부 실패에도 성공한 기사는 표시한다.

검색은 현재 목록의 제목·원문 제목·요약을 대상으로 하며 서버 재수집을 자동 실행하지 않는다. 검색어와 분야는 새로고침 후에도 유지한다.

### 실제 수집과 요약 구현 시 확정할 항목

- 네이버: 공식 뉴스 검색 API와 분야별 검색어 사용. 인증 변수 이름만 예시 파일에 작성한다.
- BBC·전자신문: 공식 RSS 안내에서 피드 주소를 선택하고 HTTPS 접근·본문/설명·발행일 필드를 확인한다.
- 네이트: 수집 가능한 공개 경로와 조건을 확인하고, 불가 시 해당 사실을 명시한다. 다른 매체 데이터로 네이트 성공을 꾸미지 않는다.
- 기사 전문에 접근할 수 없다면 제공 설명 기반임을 표시한다. 3문장 요약에 필요한 근거도 없으면 요약 불가로 처리한다.
- AI 연결 제공자는 현재 계정/환경에서 확인한 뒤 정한다. 사용자에게 키를 채팅으로 보내 달라고 요청하지 않는다.
- 키 누락 시 화면과 오류 처리는 실행 가능하게 하되, 실제 수집·번역·요약 완성 여부는 따로 보고한다.

## 6. 확인 방법

- 로컬 서버 실행 후 화면을 열고, 지정 출처별 실제 뉴스 응답을 확인한다.
- 한국어 기사와 BBC 영어 기사 각각에서 원문 제목·매체·발행일·링크를 대조한다.
- 정상 요약은 문장 3개이고 내용이 입력 근거에 있는지 검토한다.
- 분야별 필터와 검색어 조합, 없는 검색어, 검색어 초기화를 확인한다.
- 새로고침의 서버 요청과 출처별 시각 갱신을 확인한다. 캐시 재사용도 최신 수집 조회와 구분한다.
- 한 출처 실패, 키 누락, 요약 오류, 발행 시각 누락, 중복 기사를 의미 있는 서버 검증으로 확인한다.
- 데스크톱과 375px에서 카드·메뉴·검색창 가로 넘침을 확인한다.
- 화면에 테스트 자료를 쓸 경우 예시 배지를 붙이고 실제 뉴스 모드와 구분한다. 가짜 최신 뉴스는 제공하지 않는다.
- PRD 완료 기준을 체크하고 미충족 출처·설정·검증 항목을 실행 안내에 남긴다.

## 8. 제작 전 검토

현재 완성한 것은 기획서·로고 프롬프트·제작 계획서다. 다음 단계는 사용자가 계획을 검토하고 제작 여부를 선택하는 것이다. 스킬의 5단계에 따라 제작 동의 전에는 index.html과 서버 구현을 시작하지 않는다.
