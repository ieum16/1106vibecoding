# GAStudio 팀 소개 페이지 PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 v0.1 |
| 작성일 | 2026-11-06 |

PRD는 무엇을, 누구를 위해, 왜 만드는지 정리하는 제품 요구사항 문서입니다.

## 1. 배경 · 문제
사무 업무를 하는 부서는 엑셀 정리, 문서 작성, 메일 발송을 반복한다. GAStudio는 이 업무를 자동화해 업무 효율을 높이는 2인 팀이다. 어떤 업무를 요청할 수 있는지와 요청할 때 필요한 정보를 한 페이지에서 안내한다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 (가정) |
|---|---|
| 팀과 지원 업무를 쉽게 이해 | 시범 방문자 3명이 1분 안에 업무 예시를 설명 |
| 자동화 요청을 구체적으로 준비 | 방문자가 업무 설명·빈도·입출력 예시를 포함한 요청 초안을 작성 가능 |
| 문의 혼선 감소 | 자동화 요청과 사전 상담의 차이를 FAQ에서 확인 가능 |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줄 답 | 기대 행동 |
|---|---|---|---|
| 사무 업무를 주로 하는 부서 | 내 반복 업무도 자동화 가능한가? | 업무 예시, 요청 기준, 진행 절차 | 자동화 요청 준비 |
| 자동화 가능성을 먼저 묻고 싶은 담당자 | 무엇부터 설명해야 하나? | FAQ와 1:1 문의 안내 | 사전 상담 초안 준비 |

## 4. 범위
이번 범위: 한 장짜리 소개, 자동화 업무 예시, 도구 준비 중 카드, 요청 안내, FAQ, 1:1 문의. 요청·문의는 입력 내용을 복사하는 초안 작성 도구로 제공한다(가정). 복사는 실제 접수가 아님을 명확히 표시한다.

제외: 로그인, 서버 접수, 파일 업로드, 실제 메일 일괄 발송, 접수 이력 관리. 대량 메일 발송은 팀이 지원하는 업무의 소개이며 이 페이지에서 실행하지 않는다.

## 5. 정보 구조 (메뉴)
| 메뉴 | 섹션 ID | 내용 |
|---|---|---|
| 간략한 소개 | #intro | 팀 정의와 2인 팀 소개 |
| 자동화 요청 | #request | 업무 예시와 요청 초안 작성 안내 |
| FAQ | #faq | 지원 범위·준비 자료·진행 절차 |
| 1:1 문의 | #contact | 사전 상담 초안과 예시 채널 |

업무 예시(#work)와 도구(#tools)는 본문 섹션으로 제공하고 상단 메뉴는 요청한 4개만 둔다.

## 6. 화면 구성 (위에서 아래로)
헤더(로고·메뉴) → 한 줄 소개 → 자동화 업무 예시 3개 → 만든 도구(준비 중) → 자동화 요청 방법·초안 → FAQ → 1:1 문의 → 푸터.

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 제목: 반복은 줄이고, 중요한 일에 집중하세요.
- 보조: GAStudio는 단순 반복 업무를 자동화하여 업무 효율을 높이는 2인 팀입니다.
- 버튼: 자동화 요청하기 / 지원 업무 살펴보기

### 7-2. 업무 카드
| 제목 | 설명 | 요청 예시 |
|---|---|---|
| 엑셀 데이터 정리 | 반복되는 취합·중복 제거·형식 통일 지원 | 매주 여러 파일을 모아 하나의 표로 정리하고 싶어요. |
| 간단한 문서 작성 | 정해진 양식에 데이터를 넣는 문서 작성 지원 | 매달 같은 양식의 문서에 수치만 바꿔 넣고 싶어요. |
| 대량 메일 발송 | 정해진 대상에게 반복 안내하는 발송 작업 지원 | 수신자별로 안내 내용을 바꾸어 보내고 싶어요. |

### 7-3. 요청과 문의 (가정)
- 요청 입력: 업무 유형, 업무 설명, 반복 빈도, 원하는 결과. 입력 필드에 레이블을 제공한다.
- 버튼: 요청 내용 복사. 성공했을 때만 ‘복사했습니다’를 표시하고, 실패하면 직접 선택해 복사하도록 안내한다.
- 안내: ‘아직 접수되지 않았습니다. 복사한 내용을 연결된 요청 채널로 전달해 주세요.’
- 실제 채널 미정 상태에서는 ‘요청 채널 준비 중’ 표시. 예시 주소로 실제 접수가 된 것처럼 표현하지 않는다.
- 1:1 문의: 자동화 가능성을 먼저 상담하는 영역. 상담 내용 복사 기능과 예시 이메일 `team@example.com` 표시.
- 응답 시간: 운영 시간 확정 후 안내. 임의의 응답 기한을 약속하지 않는다.
- 입력 내용은 서버 전송·브라우저 영구 저장 없이 현재 화면에서만 사용한다(가정).

### 7-4. FAQ 초안 (가정)
1. 어떤 업무를 요청할 수 있나요? → 규칙이 정해져 반복되는 엑셀 정리·문서 작성·메일 발송 등입니다.
2. 무엇을 준비해야 하나요? → 업무 순서, 빈도, 입력·결과 예시를 준비해 주세요. 연습 자료에는 가상 데이터를 사용합니다.
3. 요청하면 바로 만들어지나요? → 업무 규칙과 가능 여부를 검토한 뒤 범위와 일정을 협의합니다.
4. 자동화가 가능한지 모르겠어요. → 1:1 문의에서 현재 업무를 간단히 설명해 주세요.
5. 여기서 요청이 바로 접수되나요? → 현재는 초안 작성용입니다. 실제 접수 채널은 준비 중입니다.

## 9. 반응형 · 접근성
- 375px와 1280px에서 가로 스크롤 없음. 모바일 좌우 여백 16px.
- 업무 카드: 데스크톱 3열 → 태블릿 2열 → 모바일 1열.
- 640px 미만 햄버거 메뉴: 상태 안내, 키보드 조작, 선택 후 닫힘.
- 버튼 터치 영역 최소 44px, 명확한 초점 테두리, 적절한 대비와 입력 레이블.
- FAQ는 키보드로 열 수 있는 details/summary 사용. 모션 감소 설정 존중.

## 10. 기술 조건
index.html 하나에 CSS·JS 포함. 빌드 없이 더블클릭으로 열림. 외부 의존은 선택적 글꼴 CDN만. 복사 API 미지원 시 수동 복사 안내. 실접수 서버 연결은 별도 범위.

## 11. 일정
기획 3문서 작성 → 사용자 검토·제작 확인 → 로고 또는 임시 로고 준비 → 홈페이지 제작 → 화면·기능 검토.

## 12. 완료 기준
- [ ] 상단 4개 메뉴가 해당 섹션으로 이동

- [ ] 요청 초안 복사와 문의 초안 복사가 실제 접수로 오인되지 않음
- [ ] FAQ가 마우스·키보드로 열리고 닫힘
- [ ] 375px에서 가로 스크롤 없음, 모바일 메뉴 동작
- [ ] 임시 또는 제공 로고가 헤더에 표시
- [ ] 초록 섹션·웜 뉴트럴 배경·차콜 버튼·그림자 없음 원칙 준수

## 13. 열린 질문
- 실제 요청 채널·1:1 문의 채널 및 응답 시간은 미정.
- 로고 보유 여부는 미확인. 우선 임시 로고를 사용해도 되는가?
- 요청·문의는 초안 복사 방식으로 가정. 실제 접수 연동이 필요하면 별도 결정.
- 팀 이름·업무 설명은 사용자 확정, 문구·FAQ·세부 디자인 수치는 제안.
