# ㅇㅅㅇ 팀 소개 페이지 PRD

## 한 줄 소개
취미로 게임을 만드는 1인 개발팀 ㅇㅅㅇ을 소개하는 파스텔톤 홈페이지.

배포 주소: https://ace-beta.vercel.app/

> 디자인 수정: 사용자가 제공한 참고 이미지의 중앙 정렬 대형 제목, 넓은 여백, 손그림 낙서, 브라우저 창 형태의 소개 프레임을 적용한다. 파스텔 라벤더·민트·핑크와 ㅇㅅㅇ 얼굴 로고를 유지한다. 기존 좌우 분할 히어로와 큰 캐릭터 장면은 중앙 제목 및 작은 얼굴 낙서로 대체한다.

> 콘텐츠 수정: 소개 본문에서 빗방울 게임 안내·조작 설명·게임 소개 섹션과 해당 메뉴를 제거한다. 소개 → ㅇㅅㅇ 이야기 → 다음 이야기 구성으로 표시한다. 자동 실행 게임과 우측 상단 빗방울 토글, 플레이 중 점수 및 클리어 효과는 유지한다.

> 최신 변경: 페이지 진입 시 게임을 자동 시작한다. 시작 버튼은 제거하고 우측 상단의 ‘빗방울 끄기 / 빗방울 켜기’로 제어한다. 그릇은 최대 68px × 27px로 축소하고 은은하게 표시한다. 점수는 하단에 작게 표시하며 비와 모바일 조작 버튼도 시각적 강도를 낮춘다. 아래의 기존 시작 버튼 관련 설명은 이 변경으로 대체한다. 100개 클리어와 소개 화면 유지 규칙은 동일하다.

## 1. 배경 · 문제
ㅇㅅㅇ은 취미로 게임을 개발하는 1인 팀이다. 아직 소개할 완성 게임은 없지만, 팀을 소개하고 방문자가 브라우저에서 직접 게임을 즐길 공간을 만든다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 |
|---|---|
| 팀을 쉽게 소개한다 | 첫 화면에서 이름과 취미 게임 개발을 하는 1인 팀임을 알 수 있다 |
| 방문자가 바로 게임을 즐긴다 | 설치 없이 시작하고 비 100개를 받아 클리어한다 |
| 소개 화면을 유지한다 | 게임 시작·종료 시 페이지 이동이나 새로고침 없이 콘텐츠와 스크롤 위치를 유지한다 |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 제공할 답 | 기대 행동 |
|---|---|---|---|
| 게임을 해볼 사람 | 누가 만들었고 무엇을 할 수 있는가 | 팀 소개와 조작 안내 | 빗방울 받기 플레이 |

## 4. 범위
이번 범위: 일반적인 소개 페이지, 얼굴 글자 로고, 화면 위에 겹쳐 실행되는 빗방울 받기 게임, 반응형 화면, 클리어 효과.
제외: 로그인, 서버, 온라인 순위, 게시판, 게임 다운로드, 실제 연락처 수집.

## 6. 화면 구성
고정 헤더 → 한 줄 소개와 얼굴 로고 → 개발자 소개 → 미니게임 안내 → 준비 중 카드 → 푸터.
게임은 페이지 전체 뷰포트의 투명 레이어에서 실행한다. 별도 게임 화면으로 전환하지 않는다.

## 7. 콘텐츠 상세
- 제목: 안녕하세요, ㅇㅅㅇ입니다.
- 소개: 취미로 게임을 만드는 1인 개발팀이에요.
- 보조 문구: 작은 아이디어를 조금씩, 즐길 수 있는 게임으로 만들어가요. (가정)
- 버튼: 빗방울 받기 시작
- 소개 카드: 혼자 만들어요 / 게임을 좋아해요 / 천천히 만들어가요. (가정, 기술이나 개발 이력을 지어내지 않음)
- 다음 작품: 점선 테두리와 준비 중 배지. 실제 출시 게임이 있는 것처럼 표현하지 않는다.
- 연락처: 제공된 정보가 없어 첫 버전에서는 생략. (가정)

### 7-1. 게임 규칙
1. 사용자가 시작 버튼을 누르면 비와 그릇, 받은 비 0 / 100 표시가 나타난다.
2. 비는 화면 위에서 아래로 떨어진다. 그릇은 화면 하단에서 좌우로 이동한다.
3. PC는 좌우 방향키, 모바일은 화면 하단 좌우 버튼으로 조작한다. (가정)
4. 떨어지는 빗방울이 그릇 입구를 통과하면 한 번만 집계하고 제거한다. 그릇 안에는 물이 차는 시각 효과를 표시한다. (가정)
5. 놓친 비는 제거한다. 감점·제한 시간·실패 조건은 없다. (가정)
6. 정확히 100개를 받으면 입력과 비 생성을 멈추고 남은 비를 정리한다.
7. 폭죽과 정확한 문구 '대단해요!'를 약 3초 표시한 뒤 없앤다. (3초는 가정)
8. 게임 표시·그릇·효과가 사라지며 게임은 끝난다. 소개 페이지와 스크롤 위치는 유지한다.
9. 다시 시작 버튼으로 0개부터 재플레이할 수 있고, 플레이 중 종료 버튼도 제공한다. (가정)
10. 중복 시작을 막고 종료 시 애니메이션과 입력 상태를 정리한다. 게임 레이어의 빈 공간은 페이지 클릭을 가로막지 않는다.

## 9. 반응형 · 접근성
- 375px 모바일 및 1280px 이상 데스크톱에서 가로 스크롤이 없다.
- 모바일 좌우 여백 16px, 640px 미만에서 햄버거 메뉴, 카드 1열.
- 소개는 게임을 하지 않아도 모두 읽을 수 있다.
- 버튼은 키보드로 조작 가능하고 포커스를 표시한다. 모바일 조작 버튼은 충분히 크게 만든다.
- 게임 중에만 방향키 기본 동작을 제어하고 종료 후 해제한다.
- 장식 레이어는 스크린리더에서 제외하고 진행·클리어 상태는 적절히 안내한다.
- 동작 줄이기 설정에서는 폭죽을 단순한 짧은 축하 효과로 줄인다. (가정)

## 10. 기술 조건
- index.html 하나에 CSS·JavaScript 포함, 빌드·서버 없이 브라우저로 실행.
- 투명 Canvas 등으로 게임과 폭죽 구현, requestAnimationFrame과 경과 시간 기반 이동.
- 탭 비활성화 시 게임 일시 정지, 복귀 시 비가 순간 이동하지 않게 시간값 초기화. (가정)
- 크기 변경 시 화면 경계와 그릇 위치를 보정하고 점수 유지.
- 게임 결과의 영구 저장이나 외부 데이터 전송 없음.

## 11. 제작 순서
기획 문서 → 소개 페이지와 로고 → 게임 → 클리어 효과 → 화면·동작 검증.
